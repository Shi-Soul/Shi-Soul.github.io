0. 一页结论（TL;DR）

  1. 三次范式迁移。
  2. 2022–2023：LLM 当"高层大脑"，负责选技能、写代码（SayCan、Code as Policies、VoxPoser），底层仍是传统控制或学习技能。
  3. 2023–2025：端到端 VLA 成为主线（RT-2 → OpenVLA → π0/π0.5 → Gemini Robotics → GR00T），同时出现 System 2/System 1 分层（Hi Robot、Helix、Gemini Robotics 1.5）。
  4. 2025–2026：进入"agentic robots / harness 工程"阶段。做法是把 Claude Code、Codex 这类编码 agent 的循环（工具调用、记忆、监控恢复、技能库、子 agent）整套搬到机器人上，VLA 退为 agent 可调用的一个工具。
  5. 2026 年最大的变化是"通用前沿模型直接上机器人"。 GPT-6 Astra（2026-09）、Claude Opus 5/5.5、Gemini 4 Argon（2026-10）在没有机器人专用训练的情况下，通过写代码、调用工具或直接输出数值动作，就能完成相当一部分操作和导航任务：
  6. RoboDojo 42 个任务上，GPT-6 Astra 平均成功率 22.48%，超过全部 40 个公开策略；
  7. 用 Claude Code（Opus 5）的 OpenRUA 在 CaP-Bench 上达到 99%。

但更难的通用基准仍然很低： - RobotWorld 84 个任务里，最强模型只完成 19%； - RoboQuest 上最好的 agent 只有 23%。 3. 短板一致，集中在三处。 - 实时性与精细接触：Anthropic 估计实时直接控制需要约 83Hz，而推理只有 0.2–0.4Hz； - 可靠的物理状态验证； - 成本：一次 30 秒的步态控制要调用 250 次模型、每次约 40 秒，RoboDojo 50 个实例消耗 6–11 亿 token。

结论是 LLM/agent 适合放在慢环（规划、编排、写代码、恢复），快环交给 VLA 和控制器。 4. "Harness 决定上限"已有大量证据。 同一个模型换一种接口，成功率可以差几十个点： - Show-Harness 把步长减半，零样本成功率从 60% 提到 82%； - 只加执行引擎，ASPIRE 在 LIBERO-Pro 上从 14% 提到 62%； - Physical Agency 让冻结的 VLA 在 LIBERO-PRO 上从 12.8% 提到 53.3%。

2026-10 发布的综述 Towards Agentic Robots（arXiv 2610.20442）把这一方向系统化为 Model / Data / Environment / Harness 四域。 5. 编码 agent 正在自动化机器人研发本身。 - Anthropic Project Fetch 第二阶段：Claude Opus 4.7 独立给机器狗编程，比最快的人类团队快约 19 倍； - ENPIRE：编码 agent 在真机上自动训练灵巧策略到 99%； - ASPIRE、SimEX、GaP、RATs：自己写技能、修技能、在仿真里练习。

反面证据同样重要：一项 123 轮的自改进实验发现，改进并不会自动累加，评估器和感知模块才是瓶颈。 6. 工业界的形态是"两层"。 一层是 ER/VLM 编排者，如 Gemini Robotics ER 2（Live API 流式编排、工具调用、多机协作）；另一层是 VLA 或 WAM 执行者，如 π0.7、Gemini Robotics 2、GR00T N1.7/N2（基于 DreamZero 的世界-动作模型）、Helix 02（新增 1kHz 的 System 0）。 - 模型正在 API 化：Gemini Robotics-ER API、Pi API beta（2026-10-13）、Rho-alpha 早期访问。 - 接口在标准化：MCP / ROS MCP Server、OpenClaw/ROSClaw、Anthropic 的 Model Hardware Standard（2026-08）。 7. 安全是真问题。 - RoboPAIR 证明 LLM 控制的机器人可以被越狱； - 编码 agent 会撞上明令禁止触碰的障碍物（SafeHarness）； - 不同模型提出越界动作的比率最多相差 4.8 倍（ROSClaw）。

共识是安全闸门放在模型外部：白名单、限速、时序逻辑检查、人工确认。

1. 先对齐概念：机器人研究者需要知道的 Agent 知识

1.1 一句话定义

Agent = 模型（LLM/VLM）+ 循环（观察→思考→调用工具→看结果→再决定）+ 工具 + 记忆 + 外壳（harness）。 如果把 VLA 看作"会看、会动的策略网络"，那 agent 就是任务层的闭环控制器。它的"动作"是函数调用和程序，"传感器"是工具返回值和图像，"控制周期"以秒计。

2. 全景：八条技术路线

2.1 LLM/VLM 作为高层规划器（2022–）

  • 思路：语言模型分解任务，从技能库里选下一步；技能本身由传统方法或 RL/IL 获得。
  • 代表：
  • SayCan：LLM 有用性 × 价值函数可行性；
  • Inner Monologue：把感知反馈作为文本回灌；
  • LLM-Planner、Text2Motion、LLM+P / AutoTAMP：接上经典规划和 TAMP；
  • SayPlan / ConceptGraphs / VLMaps：用场景图或语义地图 grounding；
  • KnowNo：共形预测，不确定时求助；
  • TidyBot：个性化。
  • 遗产：后来所有分层系统里的"System 2"都源于这条线；"规划器 + 可调用技能"也成了 2026 年 harness 的基本形态。
  • 局限：能力受限于技能库，规划与物理可行性之间有鸿沟，闭环反馈很粗。

2.2 代码即策略 → 编码智能体（2022–2026）

  • 思路：动作空间不是关节角，而是程序。LLM 组合感知 API、控制 API 和数学库来写策略。
  • 早期：
  • Code as Policies；
  • ProgPrompt；
  • Microsoft 的 ChatGPT for Robotics（API 库 + 提示 + 人在环）；
  • VoxPoser（LLM 写代码构造 3D 价值图）；
  • ReKep（VLM 写关键点约束、求解器实时优化）；
  • MOKA。
  • 2026 年的编码 agent 化：
  • CaP-X（ICML'26）：系统化的基准与框架，含 CaP-Gym（39 个任务）、CaP-Bench（S1–S4 单轮、M1–M4 多轮共 8 档）、CaP-Agent0、CaP-RL。核心发现是人类提供的高层抽象越少，模型越吃力；多轮交互、视觉差分、自动技能合成和集成推理能把差距补回来。CaP-RL 在真实 Franka 上做到抬方块 84%、堆叠 76%。
  • RHO：训练期由编码 agent 搜索多文件的"仓库即策略"。LIBERO-PRO 45%，π0.5 只有 12.83%。
  • Agent as Policy (AGP)：Codex CLI + GPT-6 Astra 直接驱动真实 YAM 机械臂完成装配、抛掷、叠毛巾等任务。
  • OpenRUA：只给 Claude Code 一个 ROS 2 终端（"零抽象"）。CaP-Bench 99%、LIBERO-PRO 87%；96.8% 的 episode 里 agent 自发写出感知处理程序。
  • RobotUse：agent 只做视觉选择，后端负责几何与控制。RoboLab 45%，比 CaP-X 高 6.7pp。
  • EmbodiedSWE：编码 agent 解半小时级灵巧任务，再把解扩增为 VLA 训练数据。
  • RACaP：编码移到进化期，部署时调用冻结的 Policy API，解决延迟问题。
  • 要点：代码可检查、可验证、可复用，天然适合"写一次、跑多次"；最大的瓶颈在感知和原语质量。Kuroki & Tang 的实验里，同样的 agent 在仿真特权状态下成功率 65%，只用 RGB 时降到 22.5%。

  • SafeHarness：编码 agent 在多数情况下仍撞上被禁止触碰的障碍物，推理里提到了障碍却不优先；
  • ROSClaw：不同模型提出越界动作的比率最多相差 4.8 倍；
  • Claude plays robotics 的真机片段：Grok 4.1 Fast 把玻璃门里的反射当成桌子冲过去；Opus 4.6 误判垃圾桶位置，把它拖行了几米。
  • GuardianBench（2026-08）：良性指令在特定安全场景下组合后出现的潜在风险。
  • 防护：
  • 规范检查：Safety Chip（LTL）、RoboGuard（越狱成功率 92.3%→2.3%）、SafeGate（ISO 13482）、RoboSafe（可执行谓词）、CORE（控制屏障函数，VLM 推理情境化约束）；
  • 接口层闸门：ROSClaw 安全包络、ETA 区分"想做"与"允许做"、MHS 参考文件编码限位；
  • 治理架构：ARC（2026-09，三层治理架构用于已部署自主系统）；
  • 系统化研究：SoK（2026-06，基础模型机器人的安全与隐私系统性框架）；
  • 基准：ASIMOV 系列、GuardianBench、AgentSafe。
  • 部署清单（建议）：
  • 先仿真后真机；
  • 安全检查放在模型之外：话题/服务白名单、速度、工作空间、力矩限幅；
  • 运动类命令需要人工确认（Claude Code / Codex 的权限确认可直接利用）；
  • 急停在手边；
  • 全量记录日志与录像；
  • 评估器与被评估的 agent 隔离，防止"钻评估器的空子"。

8. 开放问题与趋势

  1. 归因与公平评测：agent 的贡献和执行器的贡献如何分离？
  2. 何时调用大模型：事件触发（HarnessWAM、VLAs-as-Tools）与固定频率之间的权衡；端云协同。
  3. 物理世界里的"退出码"：怎样可靠判断"做完了""失败了""为什么失败"（Thea、LIBERO-RECOVER）。
  4. 自我改进的可累加性：评估器、感知关系理解、技能链前端偏置（123 轮研究）。
  5. 精细接触与动力学：前沿模型的系统性短板，需要 VLA/WAM 或触觉补位（GPT-6-Astra Understands Touch 显示触觉上下文有帮助）。
  6. 跨本体泛化：agent 要先"读懂"陌生机器人的能力（EMOS 的机器人简历、OpenRUA 的 openrua connect）。
  7. 权重 vs 技能：VLA 把能力烤进权重，agent 把能力写成代码。一个可能的终局是：VLA 作为可调用的底层，程序作为上层，agent 离线进化二者，再把进化出的经验蒸馏回权重（EmbodiedSWE-Gen、RACaP、HarnessPAI、InSight）。
  8. 安全、权限与治理：MHS 等硬件标准、欧盟自 2027 年起对机械中 AI 安全功能的监管、RSP 类框架如何覆盖物理能力。
