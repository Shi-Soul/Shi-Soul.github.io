五个判断

  1. LLM / agent 留在慢环。规划、编排、写代码、诊断与恢复交给 agent；10 Hz 以上的接触控制交给 VLA 和控制器。
  2. Harness 决定上限。同一个模型换个接口就能差几十个百分点：Show-Harness 把动作步长减半，零样本成功率 60%→82%；Physical Agency 让冻结的 VLA 在 LIBERO-PRO 上 12.8%→53.3%。
  3. 编码 agent 开始做机器人研发。ENPIRE 在真机上把灵巧策略自动训练到 99%；ASPIRE、SimEX 自己写技能、修技能。但一项 123 轮的实验表明，改进不会自动累加。
  4. 工业界是"两层"形态。ER/VLM 编排者 + VLA/WAM 执行者；同时在 API 化（Gemini Robotics-ER、Pi API）和接口标准化（MCP、ROS MCP Server、Anthropic MHS）。
  5. 安全闸门放在模型之外。越狱、无视约束、越界动作都已被实证；话题白名单、速度与工作空间限幅、时序逻辑检查、人工确认缺一不可。

给机器人研究者的 Agent 入门

如果把 VLA 看作"会看、会动的策略网络"，那 agent 就是任务层的闭环控制器：它的"动作"是函数调用和程序，"传感器"是工具返回值和图像，"控制周期"以秒计。

Agent = 模型 + 循环 + 工具 + 记忆 + Harness

模型
LLM / VLM（GPT、Claude、Gemini、Qwen……），负责推理、规划、写代码。它本身不能动，也不会记住上一次会话。
循环
ReAct 式的"思考 → 调用工具 → 读结果"，直到任务完成或放弃。
工具
模型可调用的函数：detect()、move_to()、vla_act()、ROS service、Python 解释器、网页搜索……
记忆
上下文窗口里的短期记忆，加上外部的场景图、失败记录、技能笔记等长期记忆。
Harness
包在模型外面的全部软件：工具协议、状态汇总、成功判定、重试策略、权限与安全闸门、日志。2026 年的大量实验表明，harness 设计往往比换模型更影响成败。

术语对照：用机器人的语言理解 Agent

LLM / VLM大语言模型 / 视觉语言模型

能读文本（和图像）的通用推理模型。

类比读过所有教科书和说明书、但没有身体的工程师

例GPT-6、Claude Opus 5.5、Gemini 4、Qwen

Agent loop智能体循环

观察 → 推理 → 行动 → 看反馈，直到完成（ReAct）。

类比任务层的 sense-plan-act 闭环

例Claude Code、Codex CLI、OpenClaw

Tool / Function calling工具调用

模型输出结构化调用（函数名 + 参数），由外部程序执行并把结果返回给模型。

类比ROS service / action 调用

例detect("cup") → {xyz, conf}

Harness外壳 / 脚手架

决定模型能看到什么、能调用什么、怎样判定成功与重试的那层软件。

类比机器人软件栈：驱动、状态机、监控、日志

例Thea、ETA、OpenRUA

Context window上下文窗口

模型一次能"看到"的全部输入：指令、历史、图像、工具结果。

类比工作内存，满了就得压缩或检索

例长任务要做历史摘要、只传必要状态

Memory记忆

跨步骤、跨任务保留的信息。

类比语义地图、场景图、失败日志

例ConceptGraphs、MessyMem

Skills技能库

可复用的程序或说明文档，agent 可以调用、也可以自己新增和修改。

类比运动基元库 / 行为库

例Voyager、ASPIRE

Code as Policy代码即策略

由模型写程序，把感知与控制 API 组合起来，程序本身就是策略。

类比工程师写的任务脚本

例Code as Policies、CaP-X

Coding agent编码智能体

能在终端里读写、运行、测试代码并迭代的 agent。

类比自动化的机器人软件工程师 / 研究助理

例Claude Code、Codex

MCPModel Context Protocol

连接模型与外部工具、数据源的开放协议。

类比rosbridge / 驱动接口标准

例ROS MCP Server、MHS

Subagent子智能体

主 agent 把子任务交给独立上下文的子 agent，只回收结论，避免上下文被细节淹没。

类比分层 / 分布式控制架构

例EMERGE-Policy、RobotUse

Reflection / Recovery反思与恢复

失败后诊断原因、修改计划或换一种执行方式重试。

类比故障检测、隔离与恢复（FDIR）

例REFLECT、DoReMi

In-context learning上下文学习

不更新权重，只看提示里的示范就学会新任务。

类比看几次示范当场调整，而不是重新训练

例RoboICL、GPT-Policy

System 2 / 1 / 0慢思考 / 快策略 / 解析控制

不同频率的三层：推理模型、学习的视觉运动策略、解析控制器。

类比任务规划器 / 学习策略 / IK·MPC·WBC

例Helix 02、GR00T N1

VLA视觉-语言-动作模型

把 VLM 微调成直接输出动作的策略。

类比语言条件的端到端视觉运动策略

例RT-2、π0.5

World model / WAM世界模型 / 世界-动作模型

预测未来观测（以及动作）的模型。

类比可学习的动力学模型 / 神经仿真器

例Genie 3、DreamZero

Post-training后训练（SFT / RL）

用监督微调或强化学习提升模型自身作为 agent 的能力。

类比策略微调

例AgenticRoboRL、CaP-RL

Guardrail安全闸门

模型的输出到达硬件之前的检查与拦截。

类比安全 PLC、速度限幅、急停

例RoboGuard、ROSClaw

一个具体例子：agent 内部在发生什么

示意，非真实日志；工具名为假设
任务  把抽屉里的蓝色积木放到桌上
① 观察  camera_rgb()          → 抽屉关着；桌上有红杯子
② 推理  积木可能在抽屉里，先开抽屉
③ 工具  detect("drawer handle") → xyz=[0.52,-0.10,0.31] conf=0.93
④ 工具  open_drawer(xyz)       → ok，位移 0.18 m
⑤ 观察  wrist_rgb()            → 抽屉里有蓝色积木
⑥ 工具  vla_act("pick up the blue block", budget=150)
                         → 结束；夹爪宽度 0 mm（没抓住）
⑦ 推理  VLA 抓取失败 → 改用解析抓取，重试一次
⑧ 工具  grasp_pose() → move_to() → gripper("close")
                         → 夹爪宽度 31 mm ✓
⑨ 工具  place_on("table")       → ok
⑩ 验证  check("blue block on table") → true（VLM + 深度复核）

这个例子说明了什么

  • 每一步都是一次模型调用，通常要几秒，所以 agent 只能管"做什么、用谁做、做完没有"，不能管每一毫秒的力矩。
  • 成功判定靠传感器，不靠模型自述。⑥ 中夹爪宽度为 0 是硬证据。这就是 Thea 所说的"评估即退出码"：软件里 exit code 是免费的，物理世界里要自己造。
  • VLA 是工具之一。接触阶段先交给 VLA，失败了换解析抓取；这种"按证据切换执行器"正是 Physical Agency、Harness VLA 的核心。
  • 工具、检查、重试规则都属于 harness。把它们设计好，同一个模型的成功率能差几十个百分点。

目前的共识

  • 语义强，物理弱。导航、指令理解、目标纠错、in-context 学习表现突出（Galbot 测得 RxR 指令导航 92%）；精确对位、动力学、双臂协调、在手操作明显落后（LIBERO-GeoMotion 只有 11.1%，步态障碍赛 0/5）。
  • 接口是最大的变量。Claude plays robotics 中，同一个模型在"写控制器 / 训 RL / 调预训练策略"上远好于扭矩直控；Astranomy 中扩展接口后成功率 80%→86%。
  • 和 VLA 组合有时有益，但不总是更好。Galbot 的 Astra + π0.5 混合控制在 RoboDojo 子集达到 48%；而在 Claude plays robotics 中，单独的 MolmoAct 比任何"LLM 监督 MolmoAct"的组合都强，Mythos Preview 还因为过于频繁地推翻 VLA 而退步。
  • 代价很高。RoboDojo 上 50 个实例要消耗 6–11 亿 token；30 秒步态需要 250 次调用、每次约 40 秒，仿真只能暂停物理来等模型。
  • 安全没解决。RoboDojo 的 Astra 评测因安全原因中止了真机测试；Claude plays robotics 的真机片段里出现了把玻璃反射当成桌子、拖着垃圾桶走了几米等事故。

安全：把闸门放在模型之外

攻击面

  • RoboPAIR：自驾 LLM、GPT 规划的地面车、商用四足全部被越狱
  • BadRobot：物理世界中的具身 LLM 越狱
  • AgentRob：论坛里的 agent 经 MCP 调度真实 Go2 / G1
  • Butter-Bench 红队：电量低时诱导机器人泄露信息来换充电

行为风险

  • SafeHarness：编码 agent 多数情况下仍撞上明令禁止触碰的障碍物，推理里提到了障碍却不优先处理
  • ROSClaw：不同模型提出越界动作的比率最多相差 4.8 倍
  • Claude plays robotics 真机片段：把玻璃里的反射当成桌子冲过去；误判垃圾桶位置并拖行数米

防护

  • 规范检查：Safety Chip（LTL）、RoboGuard（越狱成功率 92.3%→2.3%）、SafeGate（ISO 13482）、RoboSafe、CORE（控制屏障函数）
  • 接口层闸门：ROSClaw 安全包络、ETA 区分"想做"与"允许做"、MHS 在参考文件里编码限位
  • 综述：SoK：FM 机器人的安全与隐私

部署清单

  1. 先仿真后真机；真机第一次只做小幅动作，急停放在手边。
  2. 安全检查放在模型之外：话题 / 服务白名单，速度、工作空间、力矩限幅。
  3. 运动类命令需要人工确认，可以直接利用 Claude Code / Codex 的权限确认机制。
  4. 完整记录工具调用、传感器数据与视频，便于复盘。
  5. 评估器与被评估的 agent 隔离，防止 agent "钻评估器的空子"。

把 VLA 包装成 agent 的工具

用 openpi（π0 / π0.5 权重与远程推理）、LeRobot / SmolVLA、GR00T N1.6 或 MolmoAct2 作执行器，由 VLM / ER 模型（如 gemini-robotics-er-2-preview）编排。关键是让工具有界、可中断、回报结构化结果。

# 示意代码：参考 VLAs-as-Tools / Harness VLA 的接口设计思想
def vla_act(instruction: str, max_steps: int = 150) -> dict:
    """执行一个有界子任务，把结构化结果返回给 agent。"""
    for step in range(max_steps):
        obs = robot.get_observation()
        actions = policy.infer(obs, instruction)  # 例如 openpi 远程推理返回的动作块
        robot.execute(actions)
        if success_detector(obs, instruction):    # 独立的成功判定，不靠模型自述
            return {"status": "success", "steps": step}
    return {"status": "timeout",
            "gripper_width_mm": robot.gripper_width(),
            "hint": "consider analytic grasp or re-staging"}
