技术路线梳理

The Journey of DeepSeek

从 2023 年 10 月的一个代码模型，到 2026 年支持百万 token 上下文的 V4.1——DeepSeek 公开的每一份技术报告、每一个开源仓库，合起来是一条逻辑相当连贯的路线。

这篇梳理它的全部公开工作：四个阶段、四条技术主线，以及每一步与同期领域内其他工作的关系。

截至 2026-11-01 · 全部结论来自公开论文、技术报告与仓库，编号经 arXiv API 核验 · DeepSeek 同期其他工作

一句话主线：DeepSeek 把“算力受限”当作架构与系统的联合设计问题，而不是只能用钱填的缺口。它反复押注同两个方向——把参数稀疏化（MoE → 条件记忆）和把注意力与 KV 缓存压缩（MLA → DSA → CSA2/CED）——每一代都把省下来的算力换成更长的上下文、更多的强化学习，以及更低的 API 价格。

01 · 阶段

四个阶段，每个阶段解决一个不同的瓶颈

把三年的发布按“当时最紧的约束是什么”来分，刚好是四段。每一段的终点都是一个把前面积累一次性兑现的旗舰模型。

2023-10 → 2024-03补齐基本功

十八个月里把一个大模型团队该有的东西全做了一遍：代码、通用语言、MoE、数学、多模态，每个方向一篇报告加一套开源权重。这一阶段的产出单看都不算领先，价值在于把后面要用的组件都试了一遍——尤其是 DeepSeekMoE 的细粒度专家切分和 DeepSeekMath 的 GRPO，这两个零件在后面每一代里都还在。

同期 DeepSeek LLM 那篇还做了一件少见的事：自己重做了一遍 scaling law，并且给出超参数随算力的缩放关系，而不是直接套 Chinchilla 的结论。

2024-05 → 2024-12架构定型

V2 把两个自研零件拼起来——MLA（压 KV 缓存）+ DeepSeekMoE（压激活参数）——得到一个 236B 总参数、21B 激活的模型，并顺手把 API 价格打到了当时的地板价。V3 把同一套架构放大到 671B/37B，补上无辅助损失的负载均衡、多 token 预测和 FP8 训练，用 2.788M H800 卡时、14.8T token 训完。

这一阶段确立了之后不再改的骨架：MoE 主干 + 压缩过的注意力 + 为自家集群定制的训练栈。

2025-01 → 2025-12推理能力与强化学习

R1 证明了纯 RL（规则奖励、无过程监督）就能让基座模型自己长出长链推理。这一年剩下的时间 DeepSeek 在两件事上加码：把 RL 规模化（V3.1/V3.2 的后训练算力、智能体任务合成），以及把稀疏注意力从研究推进到生产（NSA → DSA）。年底的 V3.2-Speciale 拿到 IMO/IOI 金牌水平，DeepSeekMath-V2 则换了个思路——不再奖励最终答案，而是训练一个验证器去奖励推理过程本身。

2026-01 → 2026-11效率与智能体

工作重心明显从“答得对”转向“跑得起”。V4 用混合注意力把百万上下文的推理成本压到 V3.2 的 27% FLOPs / 10% KV；V4.1-Flash 进一步用 CED 架构把 prefill 激活参数降到 8B、KV 压到每 token 890 字节。同时三件新东西补齐了智能体这条线：DeepSeek Harness（自己的 agent 框架）、DSec（支撑 RL 的沙箱基础设施）、DeepInfer（生产推理引擎）。架构侧则新增了两个零件：mHC 残差连接和 Engram 条件记忆。

另一条值得注意的动向：2026 年 9–10 月连续放出 DeepGEMM-Ascend、DeepEP-Ascend、DeepJIT、clangd-ascend，把整套算子与通信栈移植到华为昇腾。

02 · 主线一

稀疏性：从条件计算到条件记忆

DeepSeekMoE→V2→V3 无辅助损失均衡→EPLB / LPLB→Engram

核心问题

给定固定的训练与推理预算，怎么把更多参数塞进模型而不等比例增加计算量。MoE 是标准答案，但 2024 年初的 MoE 有两个公认的毛病：专家容易学得雷同（冗余），以及为了负载均衡要加辅助损失，而辅助损失本身会伤害模型质量。

DeepSeek 的两步改动

DeepSeekMoE（2024-01）做了两件事，都很简单，但后来成了行业默认配置：

  • 细粒度专家切分——把每个专家切小、同时增加激活个数。组合数变多，每个专家能专精更窄的模式。
  • 共享专家隔离——留一个所有 token 都过的专家，专门吃掉通用知识，让路由专家不必各自重复学一遍。

V3（2024-12）去掉了辅助损失：改成给每个专家的路由打分上加一个可调偏置项，哪个专家过载就调低它的偏置。均衡由一个旁路的控制量负责，不再污染语言建模的梯度。这个做法现在被大量开源 MoE 沿用。

Engram：把稀疏性换一个轴

Engram（2026-01）是这条线上最新、也是概念上最跳的一步。论文的出发点是：MoE 提供的是条件计算，但 Transformer 根本没有查表这个原语——需要事实性知识时，它只能用计算去模拟检索。Engram 把经典的 N-gram embedding 现代化，做成一个 O(1) 查表模块挂在主干上。

三个值得记的结果：

  • U 形 scaling law。论文把“算力分给 MoE 还是分给静态记忆”形式化为 Sparsity Allocation 问题，发现最优配比是 U 形的——两端都不好，存在一个确定的中间最优点。
  • 收益不在预期的地方。等参数、等 FLOPs 对比下，知识类任务涨幅（MMLU +3.4）反而小于推理类（BBH +5.0）。机制分析给的解释是：查表接管了浅层的静态模式重建，等于把网络的有效深度让给了复杂推理。
  • 工程上是免费的。查表地址是确定性的，于是可以提前从主机内存预取，巨大的 embedding 表不必常驻显存。

到 V4.1-Flash，Engram 已经是 552B 主干之外额外的 196B 参数，按 token 查表稀疏访问。

03 · 主线二

注意力与 KV 缓存：被压了五代的那个数

MLA→NSA→DSA→CSA + HCA→CSA2 + CED + FP4

这是 DeepSeek 最连续、也最能说明其工作方式的一条线。每一代都在同一个指标上推进：每 token 的 KV 缓存字节数。V4.1 的报告直接给了累计战绩——相对 V4-Flash 约 1/4，相对第一代 DeepSeek 模型约 1/437。

第一步：MLA — 压缩，而不是共享

2024 年之前，省 KV 缓存的主流办法是让多个 query head 共享 key/value head（MQA、GQA）。MLA（V2, 2024-05）换了个思路：把 key 和 value 一起投影到一个低秩的 latent 向量里，缓存只存这个 latent，用的时候再升维回去。效果上它比 GQA 省得多，而且因为升维矩阵可以吸收进后续权重，推理时并不真的多一次矩阵乘。

代价是 RoPE 和低秩压缩不兼容——位置编码要作用在未压缩的维度上。V2 的解法是把位置信息拆出来单独走一路（decoupled RoPE），这个设计一直留到今天。

第二步：NSA → DSA — 从“压缩”到“只看一部分”

MLA 压的是每个 token 存多少，稀疏注意力省的是每次要看多少个 token。NSA（2025-02）是研究性的一步：三条分支并行——粗粒度压缩、细粒度选择、滑动窗口——且原生可训练，即稀疏模式在预训练阶段就在，而不是训完再剪。论文强调的另一半是硬件对齐，算术强度要平衡，否则理论 FLOPs 的节省换不成真实的加速。

DSA（V3.2-Exp, 2025-09）是把这件事落到生产：一个轻量的 lightning indexer 给所有历史 token 打分，取 top-k 进入真正的注意力计算。上线当天 API 价格下调 50%+，这是 DeepSeek 典型的做法——架构上省下来的钱直接反映到价目表上。DeepSelect 仓库后来单独开源了这个 top-k 算子，因为 torch.topk 在这个形状下慢 2–20 倍。

第三步：V4 / V4.1 — 分层与跨层复用

V4（2026-04）把注意力做成混合的：CSA（Compressed Sparse Attention）配 HCA（Heavily Compressed Attention），不同层用不同强度的压缩。百万 token 下相对 V3.2 只需 27% 的单 token 推理 FLOPs 和 10% 的 KV。

V4.1-Flash（2026-09）这一步最密集，值得拆开看，因为它基本上是把“长上下文智能体负载”这个具体场景逐项优化到底：

  • CED（Causal Encoder-Decoder）：40 层拆成 20 层因果编码器 + 20 层解码器，解码器的全局 KV 从编码器最后的隐状态投影得到，而不是每层各自算一份。结果是 prefill 只激活 8B 参数、decode 激活 16B——而智能体负载恰恰是输入远多于输出的。
  • CSA2：每个注意力层静态指定为 Full / Reindex / Reuse 三种模式之一，跨层共享主 KV 和 indexer 的 K，并复用 top-k 索引。解码器里再加一个分层稀疏 indexer，后面的索引层只在第一个 Full 层给出的候选池里挑，使深层 indexer 的开销不随上下文长度增长。
  • FP4 KV 缓存：E2M1 格式，每 16 个通道共享一个 E4M3 的 scale。合起来把常驻显存的全局 KV 压到每 token 890 字节。
  • SWA Bounded Replay：滑窗部分的 KV 干脆不持久化，需要时只重放最近 n 个 token 重建，持久化占用降到 V4-Flash 的约 1/8。

相对领域的位置

这条线上 DeepSeek 并不孤独，但方向选择有明显区别。KV 压缩的主流路线是共享（MQA/GQA，被 Llama、Mistral 等广泛采用），DeepSeek 选的是低秩压缩；长上下文的主流路线是训后外推或检索增强，DeepSeek 选的是原生可训练的稀疏注意力。CED 的思路与微软 2024 年的 YOCO（You Only Cache Once，decoder-decoder，全局 KV 只算一次）同源，但 V4.1 把它和稀疏注意力、FP4 量化、投机解码叠在了一起。

04 · 主线三

训练系统：被约束逼出来的那部分

Fire-Flyer / HAI-LLM→FP8 + DualPipe→开源周→ISCA 硬件反思→昇腾移植

这条线是理解其他三条的前提。DeepSeek 的论文里系统工作占的比重远高于同体量的实验室，而且几乎每一个架构选择都能在系统层面找到理由。

自建集群与训练栈

Fire-Flyer AI-HPC（2024-08）讲的是在万卡 A100 集群上做软硬件协同设计：自研的 HFReduce 通信库、3FS 分布式文件系统、以及一整套围绕成本和功耗的取舍。模型训练用的是自研的 HAI-LLM 框架，不是 Megatron 或 DeepSpeed。

V3（2024-12）把这套能力推到极限：

  • FP8 混合精度训练，在当时是最大规模的 FP8 训练实践之一，附带细粒度量化与高精度累加的一整套配方。
  • DualPipe：双向流水线，让前向与反向的计算和通信互相掩盖，把流水线气泡压到很低。
  • 跨节点的 all-to-all 专家通信定制内核，把 MoE 的通信开销压到能和计算重叠。

报告给出的数字是 2.664M H800 卡时预训练 + 119K 上下文扩展 + 5K 后训练 = 2.788M 卡时，按 $2/卡时折合 $5.576M。需要注意这是最终那一次训练的成本，报告自己写明不含前期研究与架构消融——传播中这个限定经常被丢掉。

开源周：把生产组件原样放出来

2025 年 2 月 24–28 日，一天一个仓库，全是线上服务在用的东西：FlashMLA（MLA 解码内核）、DeepEP（首个开源的 MoE 专家并行通信库）、DeepGEMM（FP8 GEMM，核心逻辑约 300 行）、DualPipe/EPLB/profile-data、3FS/smallpond。这批东西的影响不在论文引用上，而在于 vLLM、SGLang 等推理框架直接把它们接了进去。

反过来对硬件提要求

Insights into DeepSeek-V3（ISCA'25, 2025-05）是一篇方向相反的论文：不是讲怎么适配现有硬件，而是从 V3 的实践出发对未来 AI 硬件架构提需求。它把 MoE 通信、FP8 精度、互联拓扑上遇到的墙逐条列出来。这篇发在计算机体系结构的顶会上，受众是硬件设计者。

2026：向第二种硬件迁移

2026 年 9–10 月的一批仓库——DeepGEMM-Ascend（API 完全兼容，支持 BF16/FP8/FP4 GEMM）、DeepEP-Ascend（昇腾 950DT 上 EP8 dispatch 达 373–375 GB/s）、DeepJIT（CUDA 与昇腾共用的 JIT 运行时）、clangd-ascend（AscendC 的语言服务）——指向一件很清楚的事：把整套训练与推理栈做成可以跑在两种加速器上。DeepInfer 同时支持 NVIDIA SM100 与昇腾 950，是这件事的汇合点。

05 · 主线四

后训练：从 GRPO 到自验证

GRPO→R1-Zero / R1→奖励建模→Math-V2 自验证→智能体任务合成→在策略蒸馏

GRPO：先把 RL 做便宜

DeepSeekMath（2024-02）提出 GRPO，动机非常实际：PPO 要同时在显存里放策略网络和价值网络，价值网络和策略一样大，RL 阶段的显存开销因此翻倍。GRPO 的做法是干脆不要价值网络——对同一个 prompt 采样一组输出，用组内奖励的均值和标准差来估计优势。

这个简化的后果超出了省显存：它让 RL 微调在学术预算下变得可行，于是 2025 年几乎所有开源的推理 RL 工作都是从 GRPO 起步的。

R1：纯 RL 能长出推理

R1（2025-01）真正的贡献是 R1-Zero 这个消融：直接从基座模型做 RL，奖励只有规则判定的答案正确性和格式，没有任何过程监督、没有 SFT 冷启动。模型自己学会了延长思维链、自我检查、回溯。这件事之所以重要，是因为在此之前主流假设是推理能力需要过程奖励模型（见 OpenAI 2023 年的 Let's Verify Step by Step）或者搜索来引导。

R1-Zero 的问题是可读性差、中英混杂。完整的 R1 因此是四阶段流水线：少量冷启动 SFT → 推理 RL → 拒绝采样生成 SFT 数据 → 全场景 RL。同时发布的还有蒸馏到 Qwen/Llama 1.5B–70B 的六个小模型，这批小模型是 R1 影响力扩散最快的途径。

一个值得记的后续：R1 于 2025 年 9 月以 DeepSeek-R1 incentivizes reasoning in LLMs through reinforcement learning 发表在 Nature，据报道是首个经过同行评审的主流大语言模型。评审意见促使作者减少了拟人化表述、补充了训练数据类型与安全性的细节。补充材料给出的 R1 阶段训练成本约 $294K（不含基座模型）。

答案对不等于推理对

DeepSeekMath-V2（2025-11）正面处理 R1 范式的内在局限。论文的论点很直接：奖励最终答案这件事有天花板——答案对不保证推理对，而且定理证明这类任务根本没有可判定的数值答案。

它的做法是训练一个 LLM 验证器来判断证明的完整性与严谨性，再用这个验证器当奖励模型去训练生成器，并激励生成器在交卷前自己找出并修掉问题。关键的一招是保持“生成-验证差距”：生成器变强以后，就投入更多验证算力去标注那些难验证的证明，产出新数据继续增强验证器。结果是 IMO 2025 与 CMO 2024 金牌水平、Putnam 2024 拿到 118/120。

2026：数据流水线取代算法创新

一个有意思的转折。V4.1-Flash 的报告明确写道，后训练沿用标准的 SFT → RL → 在策略蒸馏（OPD）范式，算法上没有改动；全部实质变化都在数据流水线——大规模自动合成智能体任务与环境，并渐进扩大数据、任务和 rollout 的规模。

这也解释了 DSec（2026-09）为什么要单独写一篇：智能体 RL 需要海量有状态的隔离执行环境，一个生产规模单元约 160 个节点，每天服务约 300 万个沙箱、支撑 38 万并发、每秒创建 5000+ 个。论文还提到它与 RL 框架协同设计，把有状态的 rollout 执行与可抢占的 GPU 训练解耦，并要处理奖励投机（reward hacking）这类智能体的不良行为。

V4 的后训练还引入了另一个结构：先分别培养各领域的专家模型（各自 SFT + GRPO），再通过在策略蒸馏把它们合并成一个模型。这是规避多任务 RL 互相干扰的一种工程解法。

R1 与 Kimi k1.5 在同一周放出、结论高度一致，是 2025 年初那个“推理 RL 时刻”的两个独立证据。此后一年里开源社区的推理工作几乎都建立在这条线上。

06 · 支线

三条分支：多模态、形式化数学、推理部署

这三条线产出可观，但都不在主干演进的关键路径上——它们更像是对主线的补充或试探。

多模态与“光学压缩”

DeepSeek-VL→Janus / JanusFlow→VL2→OCR→OCR-2

2024 年的 VL 和 Janus 系列是常规跟进：Janus 的想法是把视觉理解和生成的编码解耦（两者对表征的要求不同），JanusFlow 则换成整流流。这批工作本身没有改变主干。

真正有意思的是 2025 年 10 月的 DeepSeek-OCR，它表面是个 OCR 模型，实际在问一个关于长上下文的问题：能不能把文本渲染成图片来压缩上下文？结论是压缩比在 10 倍以内时解码精度约 97%，20 倍时仍有约 60%。论文明确把这个结果指向“历史长上下文压缩”和“LLM 的记忆遗忘机制”——也就是说，这是用视觉手段攻击主线二那个问题。OCR-2（2026-01）继续推进，让编码器按图像语义动态重排视觉 token，而不是固定的从左上到右下光栅顺序。

到 V4.1-Flash，多模态终于并回主干：视觉编码器（DeepSeek-ViT，从零训练，2D-RoPE + 3×3 pixel unshuffle 下采样）从语言模型预训练一开始就在，不再是事后接上去的。

形式化数学

Prover→Prover-V1.5→Prover-V2

三代 Lean 定理证明器：V1 靠大规模合成数据，V1.5 加入证明助手反馈与蒙特卡洛树搜索，V2（2025-04）转向用 RL 做子目标分解。这条线和 Math-V2 的关系值得注意——前者在形式化系统里求可判定的正确性，后者在自然语言里训练一个验证器，两种思路对同一个问题（怎么奖励推理过程）给出了不同答案，最后 Math-V2 的路线进了主干。

推理部署与智能体基础设施

开源周内核→DSpark / DeepSpec→DeepInfer→Harness / superagent

2026 年这条线扩张得最快，也最能说明重心转移：

  • DSpark（2026-07）——置信度调度的投机解码，半自回归草稿生成。配套的 DeepSpec 是完整的训练与评测代码库，同时实现了 DSpark、DFlash 和 Eagle3 三种算法并给出同一套设置下的对比，这种“把竞品一起实现好方便公平比较”的做法在该领域不多见。从 V4-Flash-0731 开始，投机解码模块直接挂在发布的权重里。
  • DeepInfer（2026-10）——支撑线上服务的推理框架，开源了离线推理部分。附带一个坦率的清单，列出完整服务还缺什么：KV 缓存系统、VE/Prefill/Decode 分离、数据并行副本间的负载均衡。
  • DeepSeek Harness（2026-08）——自己的 agent 框架，"everything is a plugin"，建在 Cordis 之上。V4 系列之后的模型卡都用它的 minimal 模式跑代码智能体评测。dsh-superagent-prototype（2026-10）是一个更进一步的研究原型，其设计哲学写得很明确：尽可能少占用人的注意力，尽可能多产生价值。
  • TileKernels / DeepSelect / DeepJIT——新架构零件对应的算子：MoE 路由、Engram 门控、mHC 的 Sinkhorn 归一化、DSA 的 top-k。架构创新到了这个阶段，必须自带内核才能真正跑起来。

07 · 行业坐标

同一时间，领域里在发生什么

三个真正的节点

2024-05V2 与价格战

V2 以远低于同级模型的价格开放 API，直接触发了中国市场那一轮降价。这确立了之后反复出现的模式：架构效率 → 价格 → 份额。V3.2-Exp 上线当天再降 50%+ 是同一套逻辑。

2025-01R1 与那次重定价

R1 发布一周后（1 月 27 日），Nvidia 单日下跌约 17%，市值蒸发约 5890 亿美元，为当时美股单日最大跌幅。市场反应的其实不是 R1 的能力，而是 V3 报告里那个约 550 万美元的训练成本数字——即使它只涵盖最终训练。事后看，这次事件对行业叙事的改变大于对技术的改变：它让“前沿能力需要多少算力”重新成为一个开放问题。

2025-09进入同行评审

R1 登上 Nature，是主流大模型第一次走完同行评审流程。在一个技术报告普遍不接受外部审查的领域里，这是个制度性的先例。

和同期开源权重模型的分工

2024–2026 这三年，开源权重阵营大致形成了几条不同的路线，DeepSeek 的位置相当清楚：

  • Llama 系列走稠密模型 + 广泛生态，架构上保守（GQA、标准 Transformer），优势在部署与微调生态。
  • Qwen 系列走全尺寸覆盖 + 多语言，从 0.5B 到数百 B 都有，是下游微调最常用的起点——R1 的蒸馏模型也建在它上面。
  • Kimi（k1.5、K2）与 DeepSeek 的路线最接近，几次在推理 RL 和智能体能力上几乎同步，2026 年的 K3 在 V4 的基准表里是常客。
  • DeepSeek 的特征是：架构激进（每代都换注意力机制）、系统工作占比高、发布节奏与 API 价格强绑定、且把生产用的基础设施原样开源。

被采纳与被改进

衡量影响力的一个实际办法是看哪些东西被别人接着做下去：

  • GRPO 成了开源推理 RL 的默认起点，衍生改法（去偏、长度归一、裁剪策略）本身已是一个子领域。
  • 无辅助损失负载均衡被后续开源 MoE 广泛采用。
  • DeepEP / DeepGEMM / FlashMLA 被 vLLM、SGLang 直接集成。
  • mHC 是个反向的例子：它本身是对 2024 年 Hyper-Connections 的改进（把残差空间投影到流形上以恢复恒等映射），而发表后不到一年，arXiv 上已经出现十几篇 mHC 的后续工作（参数高效微调、图网络、状态空间模型、投影加速）。
  • Muon 优化器则是反过来被 DeepSeek 采纳：起源于社区博客，经 Moonshot 验证可扩展（2025-02），到 V4（2026）成为 DeepSeek 的训练优化器。

08 · 为什么是这条路

四个贯穿始终的选择

一、把约束当设计输入，而不是障碍

H800 的互联带宽低于 H100，这个事实在 V3 的技术报告里到处留下痕迹：DualPipe 要掩盖通信、FP8 要减少传输量、专家并行要定制 all-to-all 内核。ISCA'25 那篇则把这个过程反过来——从被约束的经验里总结出对硬件的要求。同样的逻辑在 2026 年延伸成昇腾移植。

二、每一代只押注能被下一代继承的东西

MLA 从 V2 活到今天，GRPO 从 DeepSeekMath 活到 V4，DeepSeekMoE 的共享专家结构三年没变。相对地，Janus 这类分支没有继承下来就停了。这种“组件复用”的纪律让每代模型的新增复杂度维持在可控范围。

三、效率收益直接兑现成价格和上下文

这是最容易被忽略、但贯穿最彻底的一条。V2 省下的 KV 缓存变成了低价 API；DSA 省下的计算当天变成 50% 降价；V4 省下的 FLOPs 变成“可以常规支持百万 token 上下文”——报告原话是这让长周期任务和进一步的测试时扩展变得可行。效率在这里不是指标，是解锁条件。

四、开源的是生产件，不是演示件

开源周放出的是线上服务正在用的内核；TileKernels 的说明里写着全部算子已用于内部训练与推理；DeepInfer 开源的是支撑生产服务的框架，并且诚实列出缺哪些组件。这种“把 battle-tested 的东西原样放出来”的做法，和只放权重或只放参考实现是两回事，也是其基础设施被下游框架快速采纳的原因。

当前的开放问题。读完全部报告，有三件事是 DeepSeek 自己也还没给出答案的：(1) Engram 的 U 形 scaling law 在更大规模下的最优点在哪，以及条件记忆能不能替代更多的 MoE 容量；(2) V4.1 的后训练已经退化成纯数据工程，那么智能体能力的瓶颈究竟在模型还是在环境合成；(3) 混合注意力（Full/Reindex/Reuse 的静态分配）目前是手工指定的，这套配置能否自动搜索。

10 · 来源与读法

这篇是怎么写的

材料全部来自一手公开内容：Hugging Face 上的模型卡（106 个模型）、GitHub 上的全部仓库说明、以及上表中的论文与技术报告。所有 arXiv 编号与标题都经 arXiv API 核验过，没有凭记忆写的引用。

两处需要读者自行判断的地方：（一）基准分数几乎都是自报的。模型卡里与前沿闭源模型的对比表由 DeepSeek 自己测得，评测脚手架、推理预算和采样参数都会显著影响结果——V4.1-Flash 的报告自己就给出了同一模型在 8 种 agent 脚手架下的差异（DeepSWE 从 65.5 到 74.2）。（二）成本数字的口径。V3 的 $5.576M 只含最终训练，R1 的 $294K 不含基座模型，报告本身都写明了，但传播中常被省略。

如果只读三篇：V2（看 MLA 怎么想出来的）、R1（看 R1-Zero 那个消融）、V4.1-Flash（看一个架构被逼到极限是什么样）。想理解这家公司为什么这么做事，加一篇 ISCA'25。
