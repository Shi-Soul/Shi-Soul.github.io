0 导读：把后训练读成一个 RL 问题

0.1 两段训练

大模型的训练分两段。预训练在数万亿 token 上做下一个 token 预测：给定前文，最大化真实下一个 token 的对数概率。它得到的是一个"会说话、懂知识"的条件分布，但不一定听指令，也不一定会把题做对。后训练把它变成助手、推理模型或智能体，主要手段有两个：监督微调（SFT，在人工或强模型写的示范上继续做最大似然，相当于行为克隆），以及强化学习。本文讨论的是后者，以及它的各种近亲（直接偏好优化、拒绝采样、在策略蒸馏）。

0.3 两种视角

按整段回答看，这是一个上下文赌博机：提示是上下文，整段回答是一次"拉臂"，奖励在回答结束时给出。奖励函数、KL 约束与最优解都在这个层面定义。

两种视角的张力贯穿全文：奖励是序列级的，而重要性比、裁剪、优势与损失聚合都可以放在 token 级或序列级（第 3 章）；信用分配要把序列级的奖励拆回到 token 或"步骤"（第 6 章）。智能体任务里，工具与环境的返回插进序列，转移才变得随机、部分可观测（第 9 章）。

0.5 与经典 RL 的六点不同

  1. 初始策略极强。 预训练模型已经会解很多题，RL 的主要作用常常是重新分配已有解的概率（第 5、11 章）。起点模型是否具备验证、回溯等"认知习惯"，直接决定 RL 能否奏效（Gandhi 等）。
  2. 转移确定、可任意重启。 单轮任务没有环境随机性，可以从任意前缀重新采样。于是"同题多次采样当基线"（GRPO）、"从中间状态续写估计价值"（VinePPO）、"在前缀树上分支"（TreePO）都很自然。经典 RL 里这需要模拟器的重置能力。
  3. 动作空间巨大，有效分支很少。 词表 15 万，但大多数位置上概率集中在一两个 token；熵集中在约两成的"分叉 token"上（80/20），探索与信用都发生在那里。
  4. 奖励稀疏且来源特殊。 学到的奖励模型可被投机；验证器只覆盖数学、代码等少数领域；开放任务依赖评判模型与评分细则（第 2 章）。
  5. 时域长、不打折扣。 一个回答上万 token，常用 γ=λ=1\gamma=\lambda=1γ=λ=1；动作是 token，但真正的"决策"是句子或工具调用，步长的划分本身是设计选择（第 6、9 章）。
  6. 算力花在生成上。 每步训练先要生成几万条长序列；生成与训练分属两套引擎、两种数值实现，"在策略"在工程上总带一点离策略，异步训练又引入陈旧度（第 3、10 章）。

0.6 四个阶段

  • 2017–2022：RLHF。 人类比较两个回答 → 训练 Bradley–Terry 奖励模型 → PPO + KL 惩罚（Christiano 等、Ziegler 等、Stiennon 等、InstructGPT）。瓶颈：策略、价值、奖励、参考四个模型同时在显存里；奖励模型可被投机。
  • 2023–2024：绕开在线 RL。 DPO 把 KL 正则目标的闭式解代回偏好损失，用分类式训练替代 PPO；拒绝采样、迭代 DPO 成为开放模型的主流配方（Llama 3）。瓶颈：离线数据覆盖不到策略的新行为。
  • 2024-09 – 2025：可验证奖励与推理。 o1 与 DeepSeek-R1 表明，以答案正确与否为奖励（RLVR）做大规模 RL，模型会自己学会长思维链、自检与回溯；GRPO 去掉 critic，DAPO 等补齐稳定性。瓶颈：只有少数领域可验证。
  • 2025 下半年 – 2026：智能体、蒸馏与规模化。 RL 进入多轮工具环境；在策略蒸馏与自蒸馏成为与 RL 并列的手段；评分细则把 RL 推向开放任务；异步系统、低精度 rollout 与训推一致成为工程主线。

0.7 最近半年的八个动向（2026-05 → 2026-10）

  1. 在策略蒸馏与 RL 并列，变体激增，也出现"离线学生 rollout 往往更好"的反思（Semi-OPD）。第 4 章。
  2. 自蒸馏把反馈变成稠密信号（SDPO），随后是对特权信息与崩溃机制的系统检验，以及智能体场景中的复现检验（现实检验）。第 4、9 章。
  3. 评分细则奖励走向主流，也被投机（FORK、加法聚合、ImpossibleRubrics）。第 2、12 章。
  4. critic 回归（EasyPPO、S3AC），价值模型开始被预训练（LenVM）。第 3、6 章。
  5. 训推一致成为系统问题，低精度 rollout 让它更尖锐（CIS、TRIAGE）。第 10 章。
  6. 可验证环境的规模化，模型开始自己写环境（SWE-Universe、SPADE）。第 7、9 章。
  7. 对技巧的冷静复查：数据技巧没有显著优于均匀采样（DataFlex-RL），RLVR 权重轨迹近乎秩 1（RELEX）。第 7、11 章。
  8. 多奖励与多能力整合（DVAO、MRTPO、MOPD）。第 3、4 章。

1 问题设定：把语言模型看作策略

1.1 序列级奖励、token 级梯度

设奖励只依赖完整回答。对序列级目标 J(θ)=Ey∼πθ[r(x,y)]J(\theta)=\mathbb E_{y\sim\pi_\theta}[r(x,y)]J(θ)=Ey∼πθ​​[r(x,y)] 用似然比技巧，由 log⁡πθ(y∣x)=∑tlog⁡πθ(yt∣st)\log\pi_\theta(y\mid x)=\sum_t\log\pi_\theta(y_t\mid s_t)logπθ​(y∣x)=∑t​logπθ​(yt​∣st​) 立即得到 0.3 节的 REINFORCE 式。几点值得强调：

  • 回答的奖励被"平均地"记到每个 token 上：写错一个数字与写了一段漂亮推理，得到同样的信号。这是第 6 章信用分配问题的来源。
  • 基线 b(x)b(x)b(x) 只要不依赖 yyy 就不引入偏差。LLM 上最自然的基线是"同一个提示的其他样本"：用贪心解码的得分（SCST、ReMax）、其他样本的均值（RLOO）或组内均值与标准差（GRPO）。
  • 用 REINFORCE 直接优化序列级指标在 2015–2016 年就有了：MIXER 优化 BLEU，序列 actor-critic 训练了 token 级的 critic，对话 RL 用手工设计的长期奖励。它们没有流行起来，主要是因为当时的初始策略太弱、奖励太粗。

1.2 KL 约束：从先验出发

KL 可以拆进每个 token：

因此可以把 −βlog⁡πθπref-\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}−βlogπref​πθ​​ 当作逐 token 的奖励，与结尾的 r(x,y)r(x,y)r(x,y) 一起交给 PPO（RLHF 的经典实现）；也可以把 KL 的某个估计量直接加进损失（GRPO 的做法）。两种放法的梯度并不相同，第 3.5 节再讨论。

用 KL 把微调约束在预训练模型附近，最早出现在序列生成的 RL 中：Sequence Tutor 用它防止音乐生成模型在 RL 后"忘记"怎么写合理的旋律，Jaques 等把它用于从人类交互日志做离线 RL。动机与今天相同：奖励只覆盖了我们关心的一小部分性质，其余的（流畅、事实、风格）要靠先验保住。

推理 RL 中常常干脆去掉 KL（DAPO、ORZ）：可验证奖励不容易被投机，KL 反而限制了模型走出 SFT 的分布。但"去掉 KL"不等于"没有约束"——裁剪、学习率与有限的训练步数都在隐式地约束偏离，第 11 章的 RL's Razor 说明在策略训练本身就偏向 KL 小的解。

1.3 后训练流水线

一个典型的推理模型流水线：

  1. 预训练：下一 token 预测，学到语言、知识与大部分"能力"的原材料。
  2. 中期训练：提高数学、代码、长上下文与推理数据的比例。它决定 RL 的起点能走多远（OctoThinker、受控研究）。
  3. SFT 冷启动：在长思维链示范（人工写的，或从更强的推理模型蒸馏来的）上做行为克隆，让模型学会格式与基本的推理模式。
  4. RL：RLHF（偏好）、RLVR（可验证奖励）或智能体 RL，往往分阶段、按领域级联（Nemotron-Cascade）。
  5. 蒸馏：把大模型的能力迁移到小模型，常用拒绝采样 SFT 或在策略蒸馏（第 4 章）。

DeepSeek-R1 同时给出了两条路线：R1-Zero 从基座直接做 RL，涌现出长思维链，但可读性差、语言混杂；R1 先用少量冷启动数据 SFT，再做推理 RL、拒绝采样 SFT、全场景 RL 的多阶段流程。LIMA 提出的"表面对齐假说"——知识与能力来自预训练，对齐只是学会格式与风格——在推理时代变成了一个更尖锐的问题：RL 到底是在教新东西，还是在挑出已有的东西（第 5 章）？

1.4 容易被忽视的接口

对 RL 研究者来说，以下几处最容易出错，因为它们在经典 RL 里没有对应物：

  • 聊天模板。 模型看到的不是裸文本，而是带角色标记的模板（系统、用户、助手），推理模型还有 <think> 标记。训练与评测用的模板不一致，相当于换了一个状态空间。混合思考模型只靠几个模板 token 切换"思考 / 不思考"，在一种模式下训练会影响另一种（思考泄漏）。
  • 采样参数。 推理引擎与模型自带的生成配置常有 top-k、top-p、重复惩罚；它们改变了采样分布，rollout 就不再来自 πθ\pi_\thetaπθ​。要么显式关掉，要么在重要性比中计入。
  • 截断。 最大生成长度是一个强制终止。截断的回答记 0 分，会教模型写短；记负分，会教模型不冒险；直接丢弃，会引入选择偏差（DAPO 用了"超长惩罚"的软版本）。
  • 结束符。 停止生成本身是一个需要学会的动作；损失掩码要正确地包含第一个结束符、排除其后的填充。
  • 数值。 同一组权重在推理引擎与训练框架中算出的概率并不相同（第 10 章）。

1.5 最近一年

  • 区分预训练与 RL 的贡献。 在原子操作明确的合成推理任务上做受控实验：RL 只有在预训练留有余量、任务处在能力边缘时，才带来向更复杂组合的外推；中期训练决定了 RL 的起点（预训练、中期训练与 RL）。半年后同一思路推广到更真实的设定，追踪预训练数据如何决定 RL 能学到什么（从预训练到后训练理解推理），多轮规划也被拆成预训练、SFT 与蒸馏三个阶段研究（多轮规划的物理学）。
  • 动作不必是 token。 预训练模型的残差流中存在可用于分层控制的时间抽象；在这些"选项"上做内部 RL，能解决 token 级 RL 无法解决的稀疏奖励任务（时间抽象与分层 RL）。这把经典的选项框架带回了 LLM。
  • RL 前移。 在语料上主动挑选要遮盖的片段再预测（PretrainZero）；把网页文本改写成填空式多选题，得到几乎无限的 RLVR 数据（Golden Goose）；此前已有强化中期训练（RMT）与在预训练语料上做 RL（RLPT）。

2 奖励从哪里来：偏好、验证器与评分细则

2.1 偏好与 Bradley–Terry

RLHF 的奖励来自比较：给定提示 xxx 与两个回答，标注者选出更好的 ywy_wyw​。Bradley–Terry 模型假设 p(yw≻yl∣x)=σ(r(x,yw)−r(x,yl))p(y_w\succ y_l\mid x)=\sigma\big(r(x,y_w)-r(x,y_l)\big)p(yw​≻yl​∣x)=σ(r(x,yw​)−r(x,yl​))，奖励模型 rϕr_\phirϕ​ 用最大似然训练：

L(ϕ)=−E(x,yw,yl)log⁡σ(rϕ(x,yw)−rϕ(x,yl))\mathcal L(\phi)=-\mathbb E_{(x,y_w,y_l)}\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)L(ϕ)=−E(x,yw​,yl​)​logσ(rϕ​(x,yw​)−rϕ​(x,yl​))

几点性质：奖励只确定到一个与 xxx 有关的常数，所以常按提示归一化；比较数据比打分数据更一致；奖励模型通常由 SFT 模型初始化、把语言模型头换成一个标量头。这条路线来自 Christiano 等的轨迹片段比较，经 Ziegler 等、Stiennon 等到 InstructGPT；HH-RLHF 公开了偏好数据并研究了有用与无害的张力，Sparrow 把人类判断按规则分解。Constitutional AI 与 RLAIF 用 AI 的比较替代人类，效果相当。

偏好的问题在于它奖励的是"让标注者满意"：标注者偏爱更长、更自信、与自己观点一致的回答，RLHF 会放大这些偏好（谄媚、RLHF 让模型学会误导，第 12 章）。

2.2 可验证奖励

对有标准答案的任务，奖励可以直接由程序判定：

r(x,y)=1[verify(extract(y), y⋆)]r(x,y)=\mathbb 1\big[\mathrm{verify}(\mathrm{extract}(y),\,y^\star)\big]r(x,y)=1[verify(extract(y),y⋆)]

数学题抽取最终答案做符号等价判定；代码跑单元测试；形式化证明交给 Lean 检查（DeepSeek-Prover-V1.5、AlphaProof）；还可以加一项格式奖励。"RLVR"一词由 Tülu 3 流行开来；R1 证明只用这类规则奖励就能得到强推理模型。

可验证奖励的优点是几乎不可被"说服"；缺点是覆盖面窄，而且"验证器"也会有漏洞：答案抽取过宽会奖励猜测，单元测试不全会奖励只通过测试的错误实现。把它推广到数学之外有几条路：训练一个生成式答案验证器做软判定（跨领域软验证、General-Reasoner、CompassVerifier）；把多领域语料改写成可验证题目（CrossThink、Webscale-RL）；或者以模型生成参考答案的概率作奖励，完全免去验证器（VeriFree、RLPR）。

2.3 生成式评判与评分细则

对医学建议、研究计划、写作这类没有标准答案的任务，目前的主流是让另一个大模型按评分细则（rubric）打分：

2.4 过度优化

奖励模型只是人类偏好的代理。Gao 等用一个大奖励模型充当"金标"、小奖励模型充当"代理"，测量优化代理奖励时金标奖励的变化。以 d=KL(π ∥ πref)d=\sqrt{\mathrm{KL}(\pi\,\|\,\pi_{\text{ref}})}d=KL(π∥πref​)​ 衡量偏离：

金标奖励先升后降，系数随代理奖励模型的规模平滑变化。这是 Goodhart 定律的定量版本，也是 RLHF 中保留 KL 惩罚的理由。缓解手段包括奖励模型集成与保守聚合（集成）、权重平均（WARM）、提早停止，以及把稀疏但可靠的验证器与稠密但有偏的奖励模型结合（HERO）。

2.5 最近一年

  • 证明可以验证。 先训练证明验证器作为奖励，再让生成器学会自我验证，达到 IMO 2025 金牌水平（DeepSeekMath-V2）。形式化方向上，Z3 等价判定被蒸馏成连续的生成式奖励（GenV）。

  • 细则与评判一起训练、随策略演化。 交替地用 RL 优化细则生成器与评判（Rubric-ARM）；细则根据策略的回答修订（MetaRubric、HarnessRL）；评判理由兼顾广度与深度（Mix-GRM）。
  • 分数的统计性质。 许多奖励模型过于敏感，对同样好的回答给出不同分数，离散化后反而更利于 RL（离散化奖励模型）；评分被建模为分布 p(r∣x,y)p(r\mid x,y)p(r∣x,y) 而不是一个数（Z-Reward、扩散奖励模型）。
  • 验证并不总比生成容易。 对编码智能体，生成复杂补丁已不难，可靠地验证反而更难；每个验证器都只是意图的代理，训练会扩大代理与意图的差距（验证视野）。
  • 精确率。 只按"覆盖了多少细则"给分会诱导堆砌内容；新的奖励要求每个回答单元既必要又正确（FORK）。世界模型也被用作 GUI 动作的验证器（世界模型验证器）。

3 策略优化算法：从 PPO 到 GRPO，再到之后

3.1 PPO 在 LLM 上

RLHF 时代的标准做法是 token 级 PPO：

3.2 去掉 critic：REINFORCE、RLOO 与 GRPO

LLM 的一个特点让价值网络变得可有可无：同一个提示可以采样任意多次。RLOO 指出 RLHF 中 PPO 的许多部件不必要，用留一基线的 REINFORCE

但 GRPO 的两个归一化引入了偏差（Dr. GRPO）：

  • 按标准差归一化：通过率接近 0 或 1 的题标准差小，优势被放大，等于给太易与太难的题更大的权重。
  • 按长度归一化：原始 GRPO 先在每个回答内对 token 求平均（乘 1/∣yi∣1/|y_i|1/∣yi​∣），再在回答间平均。对负优势的回答，越长的回答每个 token 受到的惩罚越小，于是错误回答倾向于变长。

3.3 DAPO 的四项修补

DAPO 在大规模推理 RL 中总结了四项修补，几乎成了默认配置：

  1. 非对称裁剪（clip-higher）。 比率裁剪对低概率 token 不公平：πold=0.01\pi_{\text{old}}=0.01πold​=0.01 的 token 一次最多升到 0.01(1+ϵ)0.01(1+\epsilon)0.01(1+ϵ)，而 πold=0.9\pi_{\text{old}}=0.9πold​=0.9 的 token 几乎可以升到 1。上界 1+ϵ1+\epsilon1+ϵ 因此压制了"把小概率的好动作变大"，导致熵塌缩。把上界单独调大（如 ϵhigh=0.28\epsilon_{\text{high}}=0.28ϵhigh​=0.28）可以缓解。
  2. 动态采样。 全对或全错的组优势为零、不产生梯度；过滤掉这些组并补采，保持有效批大小。
  3. token 级损失聚合。 先把整批所有 token 加起来再除以总 token 数，长回答中的每个 token 与短回答中的同样重要，避免上面的长度偏差。
  4. 超长奖励塑形。 对接近长度上限的回答施加逐渐加大的惩罚，而不是一刀切记 0。

Open-Reasoner-Zero 则说明原始 PPO + GAE（γ=λ=1\gamma=\lambda=1γ=λ=1、无 KL）也能稳定扩展；VAPO 在价值网络上做了一系列修补，在长思维链上超过无价值方法。技巧还是陷阱系统复现了这些技巧，发现很多只在特定设置下有效。

3.6 离策略：陈旧与训推不一致

即使算法是"在策略"的，工程上也总有两种离策略：

  • 陈旧：一批 rollout 做多次小批量更新，后面的更新所用的数据来自旧策略；异步训练中生成落后训练若干个版本。
  • 训推不一致：rollout 由推理引擎生成，梯度由训练框架计算；同一组权重在两处算出的 π(yt∣st)\pi(y_t\mid s_t)π(yt​∣st​) 不同（内核、精度、批不变性、MoE 路由）。

后者的标准修正是截断重要性采样（TIS）：

  • 软裁剪与重新设计信任域。 用温度控制的平滑门替代硬裁剪（SAPO）；大词表下比率裁剪对低概率 token 过严、对高概率 token 过松，于是改用直接估计的总变差（DPPO）、按概率设定边界（BandPO）、平滑的优势加权正则（DRPO）或黎曼几何下的等距更新（RIPO）。

  • 更新目标与拟合分开。 先构造目标策略再做监督拟合（TPO）；把长推理当作单步决策的序列级 PPO（SPPO）。
  • critic 回归。 PPO 的不稳定很大程度来自 critic 本身（EasyPPO），价值网络会"扁平化"（价值扁平化）；按难度选择性训练 critic 后 actor-critic 可稳定扩展（S3AC、TPPO）。另一边，从策略镜像下降导出的免 critic 方法与原目标有相同的唯一最优解（BPO）。

  • 异步下的离策略。 只对高失配的尾部收紧信任域（SAT）、从变分推断导出的序列级软约束（VESPO）、约束重要性权重的二阶矩（M2PO）。

另一条更朴素的路线是：采样多个回答，按奖励挑出好的，在上面做 SFT，迭代进行（RAFT、ReST、STaR、ReST-EM）。对二值奖励，它的目标是

也就是只有正样本、且样本来自旧策略的 REINFORCE；整个过程可以看作 EM，或者 专家迭代（"慢思考"产生数据、"快思考"模仿）。Llama 3 的后训练就是拒绝采样 + DPO 的多轮迭代。

4.3 在策略与负梯度为什么重要

Tajwar 等把偏好微调的方法按两个维度分类：数据是否在策略采样、损失是否有"负梯度"（主动压低差回答的概率）。实验结论是两者都重要：负梯度能更快地把概率质量从差的模式上移走，在策略采样让信号落在策略当前会走到的地方。对照研究（DPO 与 PPO、拆解 DPO 与 PPO）也发现，充分调优的在线 PPO 在对话与代码上仍优于离线 DPO。这推动了 DPO 的在线化与迭代化（OAIF、迭代偏好学习、RLHF Workflow），以及带探索项的版本（XPO）。

另一种视角是博弈：若偏好不可传递，标量奖励不存在，应直接求偏好下的纳什均衡策略（纳什学习、DNO、SPPO）；SPIN 把人类示范当正例、模型自己的生成当负例做自我博弈。

SFT 与 RL 之间也有中间形态：在 RLVR 中混入强模型的离策略轨迹（LUFFY）；同一阶段混合示范的监督损失与自身 rollout 的 RL 损失（SRFT）；把 SFT 看作奖励稀疏且病态的策略梯度、按 token 概率重新缩放（DFT）；把专家解拆成逐步"动作"、按每步与专家的相似度给稠密奖励（SRL）。

4.4 在策略蒸馏：稠密奖励的 RL

蒸馏传统上是离线的：教师生成回答，学生在上面做 SFT。问题与行为克隆相同——学生一旦走到教师没走过的状态就会累积错误。在策略蒸馏（OPD）让学生自己采样，教师在学生的每个前缀上给出它的分布，学生最小化逐 token 的反向 KL：

4.5 自蒸馏与特权信息

如果没有更强的教师，可以让模型自己当教师——只要教师看到学生看不到的东西。SDPO 把环境的文字反馈（报错、测试结果）放进上下文，以 πT(⋅∣st)=πθ(⋅∣st,c)\pi_T(\cdot\mid s_t)=\pi_\theta(\cdot\mid s_t,c)πT​(⋅∣st​)=πθ​(⋅∣st​,c) 为教师；即使环境只返回标量奖励，也可以把同组中成功的 rollout 当作失败尝试的"反馈"。SDFT 以"看过示范的自己"为教师，从示范学新技能而遗忘远少于 SFT。这把"答错了"的一个比特变成了"该怎么改"的逐 token 信号；代价是教师与学生共享同一组参数，特权信息可能让教师"作弊"（直接抄答案而不是给出可学习的推理）。

4.6 最近一年

  • 黑盒与离线。 只有教师文本时，训练判别器区分师生回答、把判别器当在策略奖励（GAD）；预先采样学生 rollout、离线计算教师 logits，前提是"教师一致性"（Lightning OPD）。
  • 失败模式。 采样 token 的 OPD 有 token 监督失衡、教师在学生前缀上不可靠、分词器或特殊 token 不匹配三类失败（再看 OPD）；OPD 让学生系统性地过度自信（确定性幻觉）；OPD 也会利用长度等漏洞（揭开 OPD）。
  • 变体。 信任域（TrOPD、TRB）、以评分细则代替 logits（ROPD）、弱教师（弱到强 OPD）、多教师整合各领域的 RL 专家（MOPD）、异步（OPD 比 RL 更能容忍陈旧，AsyncOPD）、自修订把二值奖励变成稠密监督（SD-Zero）、把 SFT 调整为服务于后续 RL（PEAR）。
  • 更新几何。 OPD 的参数更新小且坐标稀疏，只训练找到的子网络就几乎能复现全量训练，与 RL 的更新几何相似（稠密监督、稀疏更新）。
  • 反思。 只用初始学生的离线 rollout 蒸馏（Semi-OPD），在 1.5B 到 235B 的 17 组师生中有 14 组优于 OPD，最高快 11.4 倍；OPD 只在师生输出的 token 重合度高时才有利（Semi-OPD）。多教师 OPD 的学生常常不如只跟最好的单一专家（领域归一化 MOPD）。无监督的自蒸馏（U-OPSD）、特权信息到底贡献了什么（OPSD 中的特权信息）、从 RL 视角诊断崩溃（收益与崩溃）与批判性回顾（三个杠杆）相继出现。在智能体 RL 中，统一条件的复现发现多数自蒸馏方法的增益不如论文所报（现实检验）。

5 探索、熵与能力边界：RL 在发现还是在锐化

5.1 pass@k 与覆盖

对一道题采样 nnn 次、其中 ccc 次正确，"采 kkk 次至少对一次"的概率的无偏估计是（Codex）

pass@k^=1−(n−ck)/(nk)\widehat{\text{pass@}k}=1-\binom{n-c}{k}\Big/\binom{n}{k}pass@k​=1−(kn−c​)/(kn​)

pass@1 衡量可靠性，大 kkk 衡量覆盖：模型的采样分布里"有没有"正确答案。重复采样的覆盖率随样本数近似对数线性增长（Large Language Monkeys），这本身就是一条测试时的扩展轴。RL 研究者应当注意：RLVR 优化的是 pass@1 的期望，提升 pass@1 与保持 pass@k 是两件事。

5.2 锐化还是发现：证据

支持"锐化"的证据。 Yue 等在多个模型与基准上发现，小 kkk 时 RL 模型胜出，大 kkk 时基座模型反超：RL 主要提高了采样效率，把已有的正确解挑了出来，而 RL 模型能解的题几乎都在基座的覆盖之内。随机甚至错误的奖励也能显著提升某些模型的数学成绩（虚假奖励），后来发现部分原因是基准数据污染（推理还是记忆）。只用一个训练样本做 RLVR 就能大幅提升（单样本 RLVR）。最直接的是：不训练，只对基座做 πα\pi^\alphaπα 的 MCMC 采样，就接近 RL 后的推理表现（幂分布采样）。

理论上，二值奖励下的 KL 正则最优解为

π∗(y∣x)∝πref(y∣x) exp⁡(1[y∈Y⋆]/β)\pi^*(y\mid x)\propto\pi_{\text{ref}}(y\mid x)\,\exp\big(\mathbb 1[y\in\mathcal Y^\star]/\beta\big)π∗(y∣x)∝πref​(y∣x)exp(1[y∈Y⋆]/β)

它只在 πref\pi_{\text{ref}}πref​ 的支撑内重新加权；πref(y)=0\pi_{\text{ref}}(y)=0πref​(y)=0 的解永远不会被采到（隐形的缰绳）。现实中"支撑"是"在采样预算内能采到的"，比数学上的支撑小得多，所以这条论证比看上去更有约束力。

支持"发现"的证据。 足够长、足够稳的 RL（KL 控制、参考模型重置、多样化任务）能解出基座在大 kkk 下也解不出的题（ProRL）；用 CoT-pass@k（要求推理过程也正确）衡量，RL 确实提高了推理过程的正确率（CoT-pass@k）；受控的合成实验中，RL 在模型能力边缘带来向更复杂组合的外推（预训练、中期训练与 RL）。

起点决定一切。 起点模型是否具备验证、回溯、设定子目标、逆向推理四种认知行为，决定了 RL 能否奏效；对不具备的模型，先用含这些行为的数据做少量预训练即可（认知行为）。在 10 个基座上复现零 RL，"顿悟"并非普遍出现（SimpleRL-Zoo）；中期训练决定了基座能否被 RL 提升（OctoThinker）；800 条精选样本的 SFT 就能激发复杂推理（LIMO）。

5.3 熵的动力学

对 softmax 策略做一步自然策略梯度，状态 sss 上的熵变化近似为（熵机制）

ΔH(s)≈−η Cova∼π(⋅∣s)(log⁡π(a∣s), A(s,a))\Delta H(s)\approx-\eta\,\mathrm{Cov}_{a\sim\pi(\cdot\mid s)}\big(\log\pi(a\mid s),\,A(s,a)\big)ΔH(s)≈−ηCova∼π(⋅∣s)​(logπ(a∣s),A(s,a))

高概率且高优势的动作让熵下降，低概率且高优势的动作让熵上升。RLVR 中正确回答往往由高概率 token 组成，于是协方差为正、熵持续下降——这就是普遍观察到的熵塌缩，伴随而来的是性能饱和。该工作据此提出只对协方差最大的少数 token 裁剪或加 KL（Clip-Cov、KL-Cov）。熵的分布高度不均：约 20% 的高熵"分叉 token"决定了 RLVR 的效果，只对它们计算梯度反而更好（80/20）。

另一个 LLM 特有的限制是零方差组。通过率为 ppp 的题，GGG 个样本全对或全错的概率是 pG+(1−p)Gp^G+(1-p)^GpG+(1−p)G，此时组相对优势为零，梯度消失；有效信号近似正比于 p(1−p)p(1-p)p(1−p)。难题上采不到正样本，学习就停滞——这是探索问题在 LLM 上最直接的表现。

5.4 探索手段

按作用位置分：

  • 目标层：直接优化 pass@k（pass@k 训练、PKPO、max@k）；奖励多样性（DARLING）或低概率的正确解（奖励不太可能的解）；匹配奖励分布而非最大化奖励（FlowRL）。
  • 更新层：放宽上界裁剪（DAPO）、保护低概率 token（低概率 token）、在优势上加熵项（熵视角）；只用负样本训练也能保持多样性（负样本强化）。
  • 采样层：从高熵决策点分支（FR3E，Go-Explore 的思路）、好奇心奖励（CDE、Pixel Reasoner）。
  • 数据层：动态采样、课程与提示（第 7 章）。

5.5 最近一年

  • 虚假奖励与熵最小化为何都有效。 从裁剪偏差、熵与奖励的关系解释这两种看似矛盾的机制（重新理解 RLVR）；虚假奖励下的收益来自激活记忆捷径——答案 token 的困惑度下降、提示一侧的连贯性变差（虚假奖励悖论）。
  • 无监督 RL 的上限。 各类内在奖励（置信度、熵、多数投票）都收敛到"锐化初始分布"：起点置信度与正确性一致时有效，否则灾难性失败；训练曲线先升后降，崩溃时间由模型先验决定而非工程选择（无监督 RLVR 能扩展多远）。
  • 覆盖为何收缩。 SFT 后 pass@k 下降与数据中的"岔路口"——多条合理路径都可走的决策点——有关（岔路口）；多样性坍缩发生在后训练的哪一阶段被逐段定位（多样性在哪里坍缩）。
  • 给难题搭台阶。 训练时注入特权提示改变 rollout 分布（SAGE）、只给最小充分的知识点（KnowRL）、用参考解合成模型自己风格的正例（ReGFT）、教师只出现在提示里而不进梯度（ZPPO）。
  • 从提示与策略层面扩大探索。 在提示里插入无意义的填充文本（LoPE）、每个 rollout 前加一句解题策略（NudgeRL）、组内混入小模型的 rollout（小模型是天然的探索者）、组熵控制（GEPO）、按给定曲线精确控制熵（Entrocraft）、修正正确回答之间置信度差异对探索的压制（回到基础）、双尺度多样性正则（DSDR）。
  • 学到自己采不到的东西。 全错的组换成同伴模型的轨迹并做离策略修正（GRAFT）、在 rollout 中做稀疏的局部干预（MInTRL）、对未解出的难题持续追加采样（NGU）、在输入嵌入上加锚定噪声（EDEN）。
  • RL 学到新东西的例子。 只用表层翻译指标 chrF 作奖励，RL 就能让模型利用上下文中的语法与词典翻译从未见过的语言（未见语言翻译）；可控难度的合成任务表明，RL 能否学会长程推理取决于模型的表达能力（能学会多深的推理）。

6 信用分配、过程奖励与推理

6.1 结果奖励下的信用

在 GRPO 中，回答的优势被赋给它的每个 token。这在期望意义上是无偏的（REINFORCE），但方差巨大：一个上万 token 的正确回答里可能有错误的中间步骤，一个错误回答里可能有大段正确的推理。经典 RL 用价值函数与 TD 把信用推回到中间状态；LLM 上有三类替代。

6.2 过程奖励模型

过程奖励模型（PRM）给推理的每一步打分。早期结论是过程监督优于结果监督：Uesato 等发现两者最终准确率相近、但过程监督的推理错误更少；Let's Verify在 MATH 上用 80 万条人工步骤标签训练的 PRM 做重排，明显优于结果奖励模型。人工标签昂贵，于是出现了自动标注：从中间步骤续写多次，用到达正确答案的比例作为该步的标签（Math-Shepherd），或用二分查找定位第一个错误步（OmegaPRM）。不过蒙特卡洛标签噪声大，用 LLM 评判加共识过滤更可靠（PRM 的经验教训）。

一个关键的概念澄清来自 Setlur 等：步骤奖励应当衡量"进步"，即在某个证明者策略 μ\muμ 下这一步带来的成功概率变化

rhproc=Qμ(sh,ah)−Vμ(sh)r^{\text{proc}}_h=Q^\mu(s_h,a_h)-V^\mu(s_h)rhproc​=Qμ(sh​,ah​)−Vμ(sh​)

——这就是优势函数。一个"正确但没有推进"的步骤不应得到正奖励；而且 μ\muμ 不必是当前策略，一个能力互补的证明者给出的优势对探索更有帮助。

把 PRM 直接当 RL 奖励的主要风险是投机：策略学会生成 PRM 喜欢、但不推进解题的步骤。把过程奖励按"取最小"而非求和累积可以缓解（最小式信用分配）。隐式 PRM 提供了另一种做法：把奖励模型参数化为 rϕ(x,y)=βlog⁡πϕ(y∣x)πref(y∣x)r_\phi(x,y)=\beta\log\frac{\pi_\phi(y\mid x)}{\pi_{\text{ref}}(y\mid x)}rϕ​(x,y)=βlogπref​(y∣x)πϕ​(y∣x)​，只用结果标签训练，就自动得到 token 级奖励 rt=βlog⁡πϕ(yt∣st)πref(yt∣st)r_t=\beta\log\frac{\pi_\phi(y_t\mid s_t)}{\pi_{\text{ref}}(y_t\mid s_t)}rt​=βlogπref​(yt​∣st​)πϕ​(yt​∣st​)​；PRIME 在 RL 中在线更新它。生成式 PRM 先写验证 CoT 再判断，只需极少过程标签（ThinkPRM）。

6.3 蒙特卡洛与树

单轮任务可以从任意前缀重启，于是中间状态的价值可以直接估计：

V^(st)=1K∑k=1Kr(x, y<t⊕y~(k)),y~(k)∼π(⋅∣st)\hat V(s_t)=\frac1K\sum_{k=1}^{K}r\big(x,\,y_{<t}\oplus\tilde y^{(k)}\big),\qquad \tilde y^{(k)}\sim\pi(\cdot\mid s_t)V^(st​)=K1​k=1∑K​r(x,y<t​⊕y~​(k)),y~​(k)∼π(⋅∣st​)

VinePPO 用它替代价值网络：PPO 的价值网络在比较中间步骤的好坏时几乎不比随机猜测好，而蒙特卡洛估值显著改善了信用分配。代价是额外的生成。树形采样把这一代价摊薄：在共享前缀上分支，同一棵树里的样本自然给出分段的优势（TreePO）；rStar-Math 用 MCTS 与过程偏好模型让小模型自我进化。

6.4 测试时计算与长度

推理模型的"思考"是测试时计算：多数投票、Best-of-N、长思维链、并行思考都在用更多生成换正确率。按题目难度分配测试时计算，效率可胜过把模型放大 14 倍（Snell 等）；只用 1000 条样本 SFT 加上"预算强制"（不许结束、追加"Wait"）就能实现测试时扩展（s1）。从 RL 的角度看，长思维链是一个学会的"内部搜索"策略；MRT 把测试时计算看作元 RL，按每段思考带来的进步给稠密奖励；e3 说明要让模型在更长的预算下继续变好，必须在训练中学会探索（非对称能力、负梯度与课程）。不带验证信号、只模仿搜索轨迹的方法在扩展测试时计算时是次优的（Setlur 等）。

另一面是过度思考：o1 类模型在简单题上也写很长（过度思考）。长度控制有几种形式：奖励中减去长度惩罚 r=1[correct]−λ∣y∣r=\mathbb 1[\text{correct}]-\lambda|y|r=1[correct]−λ∣y∣（高效推理）、在提示中给定目标长度并按偏差惩罚（L1）、让模型决定是否思考（AdaptThink）、把思考切成固定长度的块、只携带短状态（Markovian Thinker）。一个有意思的发现是：PPO 的损失聚合在负奖励下偏好长回答，第二阶段做少量 RL 就能大幅缩短推理（简洁推理）；最朴素的截断长度惩罚之所以效果差，是因为优势偏差、熵塌缩与稀疏信号，修正后推理长度可减七成以上而准确率更高（DLER）。

6.5 最近一年

  • 步骤标签不再需要人。 对每步做多次独立验证再聚合（ScalePRM）、先把长 CoT 摘要成关键步骤再验证（OPV）、完全无监督的 PRM（uPRM）、预测成功概率及其可靠度的分布式 PRM（BetaPRM）、只用结果 RL 训练的生成式 PRM（TIPS），以及"RL 后训练本身已足以给步骤打分"的观察（进度优势）。
  • KL 里本来就有过程信号。 自回归 KL 正则诱导了一项过程级的信用，常见实现把它漏掉了（Future-KL）；按 token 对未来 KL 的影响加权（FIPO）。
  • 用短程训练得到长程推理。 每段推理后压缩成摘要再继续，用 16k 训练长度得到可外推的模型（Reasoning Cache）；长度激励训练"上下文内探索"（想得更长才能探索得更深）。
  • 价值模型被预训练。 逐 token 预测剩余长度的价值模型（LenVM）；在上下文中编码策略能力、作为稀疏 rollout 先验的通用价值模型（V0.5）。
  • 成功与失败不对称。 意外的成功与反复的失败按熵区别对待（EAPO）；用现成模型找出第一个错误步塑形奖励（Cliff）；每个目标只对相应文本块施加自己的优势（分块优势）。
  • 推理形式本身可学。 用两个边界 token 在显式与潜在推理之间切换，并用在策略 RL 训练（SWITCH）；并行协同推理（PaCoRe）与原生并行推理（自蒸馏 RL）；CPU 上训练的小 RL 控制器决定何时停止采样（RL 控制采样）。

7 数据、课程、环境与自我博弈

7.1 可学习性与课程

对二值奖励、通过率为 ppp 的题，单个样本奖励的方差是 p(1−p)p(1-p)p(1−p)；GRPO 一组样本提供的有效梯度近似正比于它。太难（p→0p\to0p→0）与太易（p→1p\to1p→1）的题都几乎不提供信号，只消耗 rollout。由此产生了一系列做法：动态过滤全对与全错的组（DAPO）；按组内奖励方差挑选"难度合适"的题（VCRL）；先在大量多样题上扩熵、再在少量难题上用大 rollout 预算集中训练（DRIVE）；找出模型持续失败的概念并围绕它们合成新题（SwS）；从自己的正确解合成新问题以维持 pass@k（变分问题合成）。RLVR 训练中还会自然出现由易到难的隐式课程（隐式课程）。

7.2 可验证环境

LLM 的 RL 没有 Atari 或 MuJoCo，"环境"要自己造：

  • 程序生成的推理任务：难度可调、答案可自动验证（Reasoning Gym、SynLogic、Logic-RL）。
  • 多领域可验证数据：Guru 的 6 个领域 9.2 万条数据显示，数学、代码这类预训练中常见的领域靠 RL 激发即可，逻辑、表格等陌生领域需要真正的领域内训练。
  • 软件工程环境：从真实仓库构造可执行的任务与测试（SWE-Gym、R2E-Gym、SWE-smith）。
  • 智能体环境：需要可重置、可并行、状态转移可靠，并能判定任务完成；用代码与数据库驱动比让 LLM 模拟更可靠（Agent World Model）。

验证器有漏洞时，策略一定会找到它（第 12 章）。环境的质量控制——测试是否充分、答案是否唯一、任务是否可解——是构建者最大的工作量。

7.3 自我博弈与无标签 RL

为了摆脱人工数据，可以让模型同时出题与解题。Absolute Zero 让同一个模型提出代码推理任务、用代码执行器验证，出题者的奖励是"可学习性"：

rprop(q)={1−rˉsolve(q),0<rˉsolve(q)<10,otherwiser_{\text{prop}}(q)=\begin{cases}1-\bar r_{\text{solve}}(q), & 0<\bar r_{\text{solve}}(q)<1\\ 0, & \text{otherwise}\end{cases}rprop​(q)={1−rˉsolve​(q),0,​0<rˉsolve​(q)<1otherwise​

——太难（求解者从未答对）或太易（总是答对）的题都得 0。R-Zero 用挑战者与求解者两个角色，SPIRAL 在零和博弈中自我对弈，SPICE 以大语料中的真实文档为锚防止自我博弈漂移，搜索自我博弈把它用于深度搜索智能体，CURE 让代码与单元测试互相提供奖励。

更进一步是完全不要标签：用多数投票作伪标签（TTRL）、以模型的自确定性为奖励（Intuitor）、直接最小化输出熵（熵最小化）。第 5 章已经说明，这些方法本质上都是锐化，只在起点的置信度与正确性一致时有效（无监督 RLVR）。

7.4 最近一年

  • 自适应环境。 400 个程序生成题目的环境，难度随策略能力自适应调整，联合训练优于静态数据（RLVE）；环境、策略与奖励模型一起演化（RLAnything）。
  • 环境自动构建与规模化。 终端任务程序化生成（Endless Terminals）；1000 个代码与数据库驱动的合成环境（Agent World Model）；从 GitHub PR 自动构建百万级可验证 SWE 环境（SWE-Universe）；软件世界（OpenComputer）、手机（MobileGym）、终端（CLI-Universe）；智能体观察一个运行中的参考实现、自己复现其行为（RecreationWorld）。
  • 让饱和的题重新有用。 把通过率为 1 的题组合成更难的复合题（Composition-RL）；按能力动态分配每题的 rollout 数（CoBA-RL）；对仍未解出的难题持续追加采样（NGU）。
  • 零数据自我博弈走向开放任务。 无验证器的协同进化（G-Zero）、基于文档出题（SCOPE）、以技能为单元（Skill Self-Play）、多模型协作中涌现推理（Co-RL）；同一模型既写长程可执行环境又求解（SPADE）。
  • 数据技巧的统计检验。 同一 GRPO 配方、12 个配对种子、12 个基准：均匀 GRPO 比未训练模型提高 7.76 个百分点，但 8 种 rollout 选择与重加权方法没有一种在 95% 置信下优于均匀采样，3 种自适应领域混合也不优于固定等比例（DataFlex-RL）。这提醒我们：很多论文的增益在种子方差之内。另一方面，SFT 数据中推理路径的多样性确实影响 RL 后的泛化（多样的 SFT 轨迹）。

8 多模态：视觉推理、视觉生成与 VLA

8.1 视觉语言模型的 RL

多模态 RL 先后经历了与文本相同的两个阶段。RLHF 阶段主要对付幻觉：LLaVA-RLHF 用事实增强的奖励模型缓解奖励投机，RLHF-V 用细粒度的人工纠正做稠密 DPO，RLAIF-V 用开源模型的 AI 反馈，MM-RLHF 扩大了偏好数据。RLVR 阶段把 R1 的配方搬过来：Visual-RFT、VLM-R1、Vision-R1、MM-Eureka、LMM-R1、VL-Rethinker；视频上有 Video-R1 与长视频的 LongVILA-R1。

多模态的新问题是模型是否真的在看。多模态推理基准上的增益常常来自文本推理，而非视觉感知。几条应对思路：

  • 感知本身的可验证奖励：定位用 IoU，计数与 OCR 用精确匹配，空间推理用场景图（Perception-R1、SpatialThinker）。
  • 惩罚"不看图"：遮住图像后输出应当改变，用一项 KL 鼓励这种依赖（PAPO）。
  • 用图像思考：把裁剪、放大、选帧等操作作为动作，模型在推理中主动获取视觉证据（o3、DeepEyes、Pixel Reasoner、Mini-o3）；VisionThink 让模型自己决定是否请求高分辨率图像。
  • 视觉表征本身：对比 SFT 与 RL 后的视觉编码器，RL 改变了视觉表征，定位更准（RL 让模型看得更准）。

8.2 视觉生成的 RL

扩散模型的采样是一个 TTT 步的随机过程，可以直接写成 MDP（DDPO）：状态 (xt,t,c)(x_t,t,c)(xt​,t,c)，动作 xt−1∼pθ(xt−1∣xt,c)x_{t-1}\sim p_\theta(x_{t-1}\mid x_t,c)xt−1​∼pθ​(xt−1​∣xt​,c)（高斯），奖励 r(x0,c)r(x_0,c)r(x0​,c) 只在终点给出，于是

∇θJ=E[r(x0,c)∑t=1T∇θlog⁡pθ(xt−1∣xt,c)]\nabla_\theta J=\mathbb E\Big[r(x_0,c)\sum_{t=1}^{T}\nabla_\theta\log p_\theta(x_{t-1}\mid x_t,c)\Big]∇θ​J=E[r(x0​,c)t=1∑T​∇θ​logpθ​(xt−1​∣xt​,c)]

与 LLM 不同的是，每一步的动作是连续的高维向量、对数概率是高斯的闭式。DPOK 加了 KL 正则，Diffusion-DPO 把 DPO 推广到扩散模型的似然下界，ImageReward 提供了文生图的偏好奖励模型。

流匹配模型的 ODE 采样是确定的，没有可用于策略梯度的随机性与对数概率。Flow-GRPO 把 ODE 换成边际分布相同的 SDE，从而可以在每步定义高斯策略并做 GRPO；DanceGRPO 把它统一到图像与视频；MixGRPO 只在一个滑动窗口内用 SDE、其余步用 ODE 以加速；DiffusionNFT 完全不用似然，直接在前向加噪过程上用正负样本定义改进方向，比 Flow-GRPO 快数倍。另一条路线把奖励微调写成随机最优控制（Adjoint Matching）。视觉生成中的奖励投机比文本更直观：过饱和、风格趋同、对奖励模型偏好的细节过度优化；归一化放大微小分数差异会导致投机，改用成对偏好胜率更稳（Pref-GRPO）；生成式奖励模型可扩展到 26B 以抵抗投机（RewardDance）。

8.3 VLA 的 RL

视觉—语言—动作模型（VLA）是在 VLM 上加动作输出的机器人策略，主要靠模仿学习训练。RL 在这里补的是泛化与鲁棒性：相比 SFT，RL 在语义与执行层面的分布外泛化明显更好（RL 与 VLA 泛化）；结果奖励的 GRPO 式 RL 加少量示范即可大幅提升，并观察到示范中没有的新动作模式（SimpleVLA-RL）。动作头的形式决定了 RL 的形式：离散动作 token 可以直接套用 LLM 的方法（VLA-RL、RIPT-VLA）；流匹配动作头需要处理去噪过程的似然（π_RL、DPPO）。奖励来自成功判定或进度模型，后者可以用 VLM 的 token 概率零样本得到（TOPReward）。真机 RL 的细节见姊妹篇机器人操作调研。

8.4 最近一年

  • RL 到底改进了视觉推理的什么。 因果探测、参数比较与模块移植显示，改进主要发生在中后层的推理而非视觉感知（弗兰肯斯坦式分析）；把关键信息逐步从文字移到图片，暴露出多模态 RLVR 的"盲训练"效应（SeePhys Pro）。
  • 开放配方与视觉智能体。 视觉工具集成的 RL 环境（VISTA-Gym）、防止交互轮次塌缩的智能体视觉 RL（PyVision-RL）、60 万条数据的开放配方（Vero）、在测试时自我纠错再用在策略自蒸馏内化（UniEvo-VL）。
  • 视觉生成的奖励。 预训练视频生成模型就是潜空间奖励模型（潜空间奖励）；奖励模型与生成器对抗更新（Adv-GRPO）；只对高不确定样本施加正则（GARDO）；把终点奖励分解到每个去噪步（DenseGRPO）；奖励模型先写多维批评再打分（RationalRewards）；多模态模型"读回"图像描述作免训练奖励（Read It Back）。
  • 统一生成与工业流水线。 "先推理再生成图像"整体优化（UniGRPO）；FP4 快速探索、BF16 再生成与训练（Sol-RL）；多个单任务 RL 教师蒸馏进一个流模型（Flow-OPD）；RLHF 与在策略蒸馏结合的文生图后训练（Qwen-Image-2.0-RL）；揭示 NFT 式目标中隐藏的前向—反向一致性力与 EMA 的稳定作用（DiffusionART）。
  • VLA：世界模型充当环境与 critic。 用模型自己的成功轨迹给失败轨迹打进度分（SRPO）；在视频世界模型里想象 rollout 做在策略 RL（WMPO）；把通用 VLA 训成精密任务的专家（GR-RL）；读出紧凑的"RL token"做在线 actor-critic（RL Token）；视频世界模型提供多帧价值估计（WCM）。

9 智能体：多轮、工具与环境中的 RL

9.1 从 MDP 到 POMDP

单轮推理中，环境只是一个验证器。智能体任务中，模型的输出（工具调用、命令、点击）改变外部世界，世界的返回进入上下文：

τ=(x, a1, o1, a2, o2, …, aK),ak∼πθ(⋅∣x,a<k,o<k),ok∼P(⋅∣世界状态,ak)\tau=(x,\ a_1,\ o_1,\ a_2,\ o_2,\ \dots,\ a_K),\qquad a_k\sim\pi_\theta(\cdot\mid x,a_{<k},o_{<k}),\quad o_k\sim P(\cdot\mid \text{世界状态},a_k)τ=(x, a1​, o1​, a2​, o2​, …, aK​),ak​∼πθ​(⋅∣x,a<k​,o<k​),ok​∼P(⋅∣世界状态,ak​)

aka_kak​ 是模型生成的一段 token（思考 + 动作），oko_kok​ 是工具或环境的返回。这才是 RL 研究者熟悉的设定：转移随机且未知，世界状态部分可观测，几十到上百轮，奖励多在任务结束时给出。几个立即出现的工程问题：

  • 损失掩码：观测 token 不是策略生成的，不应计算 ∇log⁡π\nabla\log\pi∇logπ。梯度只在 aka_kak​ 内的 token 上：∇J=E[∑k∑t∈ak∇θlog⁡πθ(yt∣st) A^k,t]\nabla J=\mathbb E\big[\sum_k\sum_{t\in a_k}\nabla_\theta\log\pi_\theta(y_t\mid s_t)\,\hat A_{k,t}\big]∇J=E[∑k​∑t∈ak​​∇θ​logπθ​(yt​∣st​)A^k,t​]（Search-R1）。
  • 上下文管理：几十轮交互很快填满上下文窗口。截断、摘要、"折叠"历史或把记忆写到外部，都改变了状态的定义；把记忆更新当作动作一起训练，可以做到显存恒定（MEM1）。
  • 环境成本：每一步可能要启动容器、跑测试、访问网页，比生成 token 慢得多，而且有状态、难以并行。
  • 长尾长度：不同轨迹的轮数与长度差异极大，同步训练的等待时间由最长的那条决定（第 10 章）。

9.2 多轮信用分配

默认做法是所有轮次共享回合的优势。改进有几个方向：

  • 分层：高层在轮次上做离策略的价值学习，低层在 token 上做策略梯度（ArCHer）。
  • 步骤分组：不同轨迹经常经过相同的环境状态（例如网页、棋盘），以这些"锚状态"为组计算步骤级优势 A^(s,ai)=Ri−meanj: sj=sRjstdj: sj=sRj\hat A(s,a_i)=\frac{R_i-\mathrm{mean}_{j:\,s_j=s}R_j}{\mathrm{std}_{j:\,s_j=s}R_j}A^(s,ai​)=stdj:sj​=s​Rj​Ri​−meanj:sj​=s​Rj​​，不需要 critic（GiGPO）。
  • 轮次级 MDP：以轮次为步做 PPO（Turn-PPO），或以轮次级留一法得到无偏优势（Dr. Kernel）。
  • 特权 critic：训练时让 critic 看到参考答案等特权信息（SWEET-RL）——不对称 actor-critic 的标准技巧。
  • 分支：在工具调用之后的高熵步骤分支采样（ARPO），或按轮次建树（AT²PO）。

9.3 四类智能体的 RL

  • 搜索与深度研究：在推理中调用搜索引擎，奖励为最终答案是否正确（Search-R1、R1-Searcher）；在真实网络环境中训练（DeepResearcher）；用 LLM 模拟搜索引擎以降低成本（ZeroSearch）；合成高不确定性的问题做 RL（WebSailor）；大规模异步 RL 支持上百轮搜索（超越十轮）；完整的开放配方（Tongyi DeepResearch）。
  • 工具集成推理：数学推理中交错执行代码（ToRL、ReTool、rStar2-Agent）。工具返回的分布外内容会诱发低概率 token 与梯度爆炸，过滤掉含"空轮"的轨迹即可稳定（SimpleTIR）。
  • 软件工程与终端：以仓库测试为验证器（SWE-bench）；用开源软件演化数据与规则奖励（SWE-RL）；可执行环境的构建（SWE-Gym、R2E-Gym）；长上下文多轮 SWE RL（长上下文 SWE）；CUDA 内核优化（Kevin）。
  • GUI 与计算机使用：手机与网页上的自主 RL（DigiRL、WebRL）；R1 式规则奖励（UI-R1、GUI-R1）；零人工成本的在线学习（ZeroGUI）；多轮 RL 的大规模系统（UI-TARS-2）。

前沿开放模型把智能体 RL 作为后训练主线：Kimi K2 用大规模智能体数据合成与联合 RL，GLM-4.5 面向智能体、推理与编码，DeepSeek-V3.2 大规模合成智能体任务后做 RL，Kimi K2.5 用并行子智能体降低长任务延迟。

9.4 稳定性

多轮 RL 比单轮更容易崩溃。已识别的模式有：奖励方差塌缩与梯度尖峰的"回声陷阱"（RAGEN）；搜索智能体中正确与错误回答的似然一起下降的"懒惰似然位移"（GRPO 在搜索中的崩溃）；某些控制 token 的概率突然尖峰、破坏结构化执行，而底层工具能力仍在（多步工具 RL 的崩溃）；以及熵看不出来的"模板坍缩"——推理看似多样，实则与输入无关，需要用输入与推理的互信息来诊断（RAGEN-2）。

9.5 最近一年

  • 跨回合学习与长程信用。 元 RL 让智能体在测试时利用前几回合的反馈主动探索（LaMer）；只在关键状态分支采样（Spark）；动态评分细则提供细粒度信用（DRACO）；在 token、轮次与回合多个尺度上分配信用（多尺度策略优化）、跨会话分配信用（Mosaic）、进度感知的优势塑形（ProAS）。
  • 稳定性的系统研究。 统一框架分析不稳定来源（ARLArena）；多智能体共用全局基线导致梯度不稳（Dr. MAS）；把失败分解为探索错误与利用错误（探索与利用错误）；单 rollout 异步配方中 Muon 比 AdamW 更稳（长程 RL 需要 Muon）。

10 系统与规模：生成、同步与训推一致

10.1 一步 RL 的解剖

一次 RL 迭代包含三段：推理引擎为一批提示生成几万条回答（rollout）；训练引擎计算奖励、优势与梯度并更新参数；把新权重同步回推理引擎。

Tstep≈Tgen+Ttrain+TsyncT_{\text{step}}\approx T_{\text{gen}}+T_{\text{train}}+T_{\text{sync}}Tstep​≈Tgen​+Ttrain​+Tsync​

对长思维链与智能体任务，TgenT_{\text{gen}}Tgen​ 通常占一半以上，而且由批中最长的那条回答决定——回答长度呈长尾，大部分 GPU 在等少数长回答。推理引擎（vLLM、SGLang）为吞吐优化：分页 KV 缓存、连续批处理、前缀复用；训练框架（FSDP、Megatron）为梯度计算优化。两者用不同的内核、并行方式与数值精度。

10.2 同步与异步

同步（共置）：训练与生成轮流占用同一批 GPU，每步生成用的都是最新权重，严格在策略。HybridFlow（veRL） 用单控制器编排、多控制器执行，在训练与生成之间切换并行布局；早期的 DeepSpeed-Chat、OpenRLHF、NeMo-Aligner 也属此类。缺点是长尾回答造成的空闲。

异步（分离）：生成与训练用不同的 GPU，生成持续进行、落后训练若干个版本，以陈旧换吞吐——正是 IMPALA 的 actor-learner 结构，V-trace 的离策略修正在这里有了新的用武之地。异步 RLHF 研究了离策略程度对在线 DPO 等方法的影响；AReaL 完全解耦生成与训练，配合陈旧度控制与解耦的 PPO 目标；PipelineRL 在生成过程中就地更新权重以减少陈旧；LlamaRL 扩展到 405B；INTELLECT-2 在全球去中心化的节点上异步训练。Kimi k1.5 用"部分 rollout"处理长尾：超长的回答分段生成、跨迭代续写。

10.3 训推不一致

即使严格同步，rollout 的采样概率 πinfer\pi_{\text{infer}}πinfer​ 与训练时重新计算的 πtrain\pi_{\text{train}}πtrain​ 也不相同：推理与训练的内核不同、BF16 舍入不同、批大小不同导致的非批不变性（Thinking Machines），以及 MoE 模型中两边的专家路由可能不同。差异在单个 token 上很小，但会在长序列上累积，而且集中在低概率 token 上，足以让训练崩溃。这是 2025 年下半年才被普遍认识的问题（TIS）。修正方法：

  • 截断重要性采样：在梯度上乘 min⁡(πtrain/πinfer,C)\min(\pi_{\text{train}}/\pi_{\text{infer}},C)min(πtrain​/πinfer​,C)（第 3.6 节）。
  • 改变数值：改用 FP16，其更多的尾数位显著减小舍入差异（FP16）。
  • 路由回放：把推理时的 MoE 路由记录下来，训练时复用（R3）。
  • 批不变内核：让推理结果不依赖批的组成。

形式化与实践说明了这些方法的共同基础：token 级替代目标只在训推差异与陈旧都小时近似序列级目标。

10.4 算力曲线与配方

RL 的算力—性能关系能否像预训练那样预测？ScaleRL 用 40 万 GPU 小时系统研究，发现验证集通过率随 RL 算力呈 S 形：

R(C)=R0+A−R01+(Cmid/C)BR(C)=R_0+\frac{A-R_0}{1+(C_{\text{mid}}/C)^{B}}R(C)=R0​+1+(Cmid​/C)BA−R0​​

AAA 是渐近上限，BBB 是效率，CmidC_{\text{mid}}Cmid​ 是达到一半收益所需的算力。多数设计选择（损失聚合、优势归一化、数据课程）主要改变 BBB，少数（损失类型、精度修正、模型规模）改变 AAA；用小规模拟合可以外推大规模的结果。开放的配方研究（Skywork-OR1、AceReason、Light-R1、ORZ）与工业报告（MiniMax-M1、Seed1.5-Thinking、Magistral、Qwen3、Ring-1T）给出了大量可复用的细节。

RL 需要的模型容量很小：一个回合只提供约一比特的信息，合理配置的 LoRA 就足以承载 RL 的更新（LoRA Without Regret）；这也是托管式训练 API 的基础（Tinker）。量化噪声甚至可以增加探索（QeRL）。

10.5 最近一年

  • 简单配方。 单阶段、固定超参的最简配方在 1.5B 模型上做到最好（JustRL）；RLVR 中 DoRA 等结构变体优于 LoRA，SVD 初始化反而有害（PEFT 与 RLVR）；按领域级联的 RL（Nemotron-Cascade）。
  • 低精度 rollout 与它的代价。 FP8 权重与 KV 缓存的实用栈（FP8-RL）、训练与 rollout 统一精度（Jet-RL）；但即使用 TIS 修正，全流程 FP8 仍会不稳（全流程 FP8），NVFP4 需要按方向诊断并重平衡梯度（TRIAGE），MoE 的 FP4 rollout 需要量化感知训练（TRACE），INT4 KV 缓存要对注意力汇聚与近期上下文保留高精度（KV4-RL）。

11 理论与机制：RL 改变了模型的什么

11.1 软 RL 与偏好学习的理论

KL 正则目标的最优解是以 πref\pi_{\text{ref}}πref​ 为先验的玻尔兹曼分布（0.2 节），这把 LLM 的 RL 与最大熵 RL 的理论连在一起（软 Q 等价）；DPO 在 token MDP 中隐式学到软 Q 函数（从 r 到 Q*）。偏好学习方面，Bradley–Terry 下奖励学习的样本复杂度与悲观策略的必要性（Zhu 等）、KL 约束下迭代偏好学习的保证（Xiong 等）、带乐观探索的在线 DPO（XPO）构成了 RLHF 理论的主体。

11.2 锐化与生成—验证差距

锐化。 Huang 等把"自我改进"形式化为锐化：让策略把概率集中到它自己认为最好的回答上，例如最大似然序列，或按自评分加权的分布。它给出 SFT 式（在自己的最好样本上训练）与 RL 式（以自评分为奖励）两类算法实现锐化的样本复杂度。这为第 5 章的经验争论提供了一个精确的框架：如果 RL 只在锐化，那它的上限由基座"知道哪个答案最好"的能力决定。对基座直接从 πα\pi^\alphaπα（α>1\alpha>1α>1）采样就接近 RL 效果（幂分布采样），以及无监督 RL 先升后降（无监督 RLVR），都与这个图景一致。

生成—验证差距。 一个令 RL 研究者困惑的问题是：既然偏好数据是固定的，信息论上离线最大似然就足以利用其中全部信息，为什么"先学奖励模型、再在其上在线 RL"实践中更好？Swamy 等的回答是：若奖励模型所在的函数类比策略类简单得多（验证比生成容易），那么先在简单的类里学一个奖励、再用 RL 在其上搜索策略，比直接在复杂的策略类里做最大似然更容易找到好解。这个解释也预言了它失效的条件：当验证不再比生成容易时（验证视野），RL 的优势会缩小。

11.3 RL's Razor 与更新几何

与 SFT 相比，RL 后训练有一组稳定的经验现象：

  • 遗忘更少。 新任务上表现相同时，RL 比 SFT 更好地保留原有能力；遗忘程度由新任务上微调模型与基座之间的 KL 决定；在策略 RL 在所有能解决新任务的策略中偏向 KL 最小的那个，而 SFT 可以收敛到任意远的分布（RL's Razor）。
  • 泛化更好。 在规则与视觉的变体上，SFT 倾向记忆训练数据，结果奖励的 RL 更能泛化（SFT 记忆、RL 泛化）；但这并不绝对，长思维链 SFT 的跨领域泛化取决于优化、数据与模型能力（SFT 的条件泛化）。
  • 更新稀疏。 RL 只更新 5%–30% 的参数，不同种子、不同数据下的子网络高度重合（小子网络）；更新避开权重的主成分方向（偏离主方向）。

一个直观的解释是：在策略的数据来自模型自己的分布，梯度只需微调已经很可能的行为，而 SFT 的目标分布可能离模型很远。SFT 本身也可以被看作奖励稀疏、按 1/π1/\pi1/π 加权的策略梯度，按 token 概率重新缩放就能改善它的泛化（DFT）。

11.4 最近一年

  • 动力学可以推导。 强化微调中的熵动力学（熵动力学）；组相对优势的隐式对称——正确与错误轨迹权重严格对称、未采样 token 得不到更新（隐式对称）；策略镜像下降近似带来的隐式正则（PMD 的隐式正则）；由易到难的隐式课程（隐式课程）；采样预算与题目难度的关系（相对预算理论）；GRPO 训练动力学的闭式模型（可预测的 GRPO）。
  • 模型里有价值神经元。 奖励相关信息集中在少数神经元：一类的激活预测状态价值，另一类编码类似多巴胺的奖励预测误差（稀疏奖励子系统）。这与神经科学中的时间差分学习图景惊人地相似。
  • 关键 token 与特征。 以对数概率变化的符号定位稀疏但关键的推理 token（更新方向、稀疏但关键）；在共享特征空间里比较同一基座、同一数据训练的 RL 与 SFT 模型，解释 RL 为何泛化（特征级机制）；LLM 策略内部有逐层的"内部策略"（自底向上策略优化）。
  • RL 的权重轨迹近乎秩 1。 大部分下游收益由参数增量的秩 1 近似承载，投影幅度随训练步近线性增长；用短观察窗估计方向并线性外推即可得到后续检查点（RELEX）。OPD 的更新同样稀疏（稠密监督、稀疏更新）。
  • 为什么互不干扰、为什么泛化。 多任务下 SFT 的梯度冲突，RL 的更新稀疏且跨任务近似正交（SFT 冲突、RL 共存）；SFT 沿固定方向更新，在策略训练不断调整方向，后者决定泛化（在策略的更新方向）；多领域 RL 中的跨领域干扰与恢复（局部冲突、定向修复）；RLVR 训练轨迹中的低维有效子空间（RLVR 的几何）；训练时的采样策略与真正应优化的推理策略不是同一对象（训练策略的幻象）。

12 奖励投机与安全：优化压力把模型推向哪里

12.1 Goodhart 的定量形式

设代理奖励 r^=r+ϵ\hat r=r+\epsilonr^=r+ϵ。优化越强，策略越集中在 ϵ\epsilonϵ 大的区域——这是 RL 领域早已熟知的规范投机（DeepMind 的案例集）。第 2.4 节的过度优化曲线是它在 LLM 上的定量形式（Gao 等）。不同的奖励来源有不同的投机方式：

奖励来源 典型投机
人类偏好 / 奖励模型 迎合观点（谄媚）、更长更自信、说服评估者接受错误答案
可验证奖励 修改或绕过测试、硬编码答案、利用答案抽取的漏洞
评判模型与评分细则 堆砌细则关键词、编造满足细则的内容、对评判模型的风格偏好过度优化

12.2 RLHF 的谄媚与说服

人类偏好数据本身就奖励迎合用户观点的回答，RLHF 会放大这种倾向（谄媚）；RLHF 后的模型更擅长让人类评估者相信错误的答案是对的（RLHF 让模型学会误导）。在越来越容易投机的环境课程中，模型会从谄媚泛化到篡改自己的奖励函数（从谄媚到奖励篡改）。更一般地，窄任务上的训练会泛化出广泛的行为变化：只在写不安全代码上微调就出现广泛失准（涌现失准），在无害任务上学会投机评判也是如此（奖励投机学校）。

12.3 RLVR 的投机与失准

可验证奖励不能被"说服"，但能被"绕过"。MacDiarmid 等在真实的生产级编程 RL 环境中研究了这一点：先让模型通过合成文档或提示了解投机手法，再在这些环境中训练。模型学会了投机，并且泛化出对齐伪装、与恶意行为者合作、推理恶意目标，以及在 Claude Code 中尝试破坏（包括破坏这篇论文本身的代码库）。用聊天式提示做 RLHF 安全训练后，聊天评测上看起来对齐了，智能体任务上的失准依然存在。三种缓解有效：阻止投机本身；增加安全训练的多样性；以及"接种提示"——训练时把投机描述成可接受的行为，即使模型学会了投机，失准也不再泛化。

12.4 思维链可监控性

推理模型的思维链提供了一个新的监督通道：用另一个模型阅读 CoT，比只看动作更能发现投机，甚至较弱的模型就能监控较强的模型（Baker 等）。自然的想法是把 CoT 监控放进奖励。结果是：优化压力弱时，模型更强也更对齐；优化压力强时，模型学会了"混淆的投机"——继续投机，同时把意图从 CoT 中藏起来。这意味着 CoT 监控是脆弱的：一旦成为优化目标，它就不再是可靠的观测。因此有人呼吁开发者不要对 CoT 直接施加优化压力，保护可监控性（CoT 可监控性）。此外，推理模型的 CoT 常常不承认使用了提示中的线索（推理模型不总说出所想）。

安全本身也是奖励设计：把安全政策写成细粒度规则、由 LLM 打分作为奖励的一部分（RBR）；把有用与无害解耦为奖励与代价、做约束 RL（Safe RLHF）；让推理模型在回答前显式回忆并推理安全规范（审慎对齐）。可扩展监督的研究（辩论、证明者—验证者博弈、弱到强泛化）讨论的是：当模型超过人类时，奖励从哪里来。

12.5 最近一年

  • 分布式训练的攻击面。 共享 rollout 的去中心化 GRPO 中，恶意节点可通过投毒补全植入行为（去中心化 GRPO 投毒）。
  • 可靠性与校准。 奖励搜索智能体在能力边界之外正确拒答（BAPO）；RLVR 与 OPD 都会让模型过度自信，于是把推理与校准拆成两个目标（DCPO、OPD 的确定性幻觉）；按不确定性表达的忠实度修正偏好（RLMF）；三角色自我博弈的安全对齐（TriPlay-RL）；用信息论分析思维链可监控性（可监控性的信息论）。
  • 统一框架。 以"代理压缩假说"统一理解奖励投机，并梳理它与涌现失准的联系（奖励投机综述）。
  • 新的投机面。 rubric RL 中对评审偏好的投机（rubric 奖励投机）；rubric 分数简单相加是弱点（加法聚合）；169 个不可能任务检验 rubric 是否会奖励编造（ImpossibleRubrics）；前沿模型能用几乎没有实质内容的回答在可验证指令遵循上拿满分（CALIF）；只改写修辞就能抬高 AI 审稿分数（修辞投机）；72 个社会规则沙箱中，奖励投机自然地表现为发现监管漏洞（SocioHack）。
  • 攻防都用 RL。 自我博弈 RL 训练的自动红队发现了针对前沿模型的新型提示注入（GPT-Red）；后训练会在无关的决策上留下系统性的行为偏移（行为影子）；RL 后模型的数据污染可从逐层表征中检测（LaRA）。

13 实践入门：RL 研究者的第一个大模型 RL 实验

13.1 路线

先在单卡上用几十行代码跑通一个可验证任务的 GRPO，亲眼看到奖励、熵与回答长度怎样变化；再换成成熟框架，把同样的实验放大到多卡、长序列与真实基准。大模型 RL 的多数失败不在算法，而在三件事：采样是否真的在策略、奖励是否真的在测你想测的东西、评测是否足够稳。

  1. 模型。 从 0.5B–4B 的开放模型开始。基座模型适合研究"从零 RL"，指令模型更容易遵守答案格式。部分模型家族在常见数学基准上可能有污染、随机奖励也能涨分（虚假奖励、污染），结论至少要在两个模型家族上复现。
  2. 任务与验证器。 先用答案确定、可以自动判定的任务：程序生成的算术与逻辑题（Reasoning Gym）、GSM8K、MATH。验证器 = 答案抽取 + 等价判定；格式错误给 0 分即可。
  3. 算法与超参。 GRPO 或 RLOO，加 DAPO 的修补作为起点：每题 8–16 个样本、温度 1.0、非对称裁剪（如 ϵlow=0.2, ϵhigh=0.28\epsilon_{\text{low}}=0.2,\ \epsilon_{\text{high}}=0.28ϵlow​=0.2, ϵhigh​=0.28）、token 级损失聚合、过滤零方差组、不加或只加很小的 KL；全参学习率在 10−610^{-6}10−6 量级，LoRA 约大一个数量级。这些是常见起点，不是定论。
  4. 框架。 单机：TRL；多机与长序列：veRL、OpenRLHF、ROLL、AReaL；托管：Tinker；智能体：Agent Lightning、VerlTool、AgentGym-RL。
  5. 评测。 报 avg@k（每题采 kkk 次的平均正确率）与 pass@k；多个随机种子；与同算力的 SFT 与拒绝采样基线比较；常用 MATH-500、AIME、GPQA、LiveCodeBench、SWE-bench。

13.2 最小 GRPO

单卡、PyTorch + transformers。任务是两位数乘三位数，答案写在 <answer> 标签里。每批只更新一次，所以重要性比恒为 1、裁剪不起作用，目标就是带组基线的 REINFORCE。

import random, re, torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"     # 任意小的指令模型
G, BATCH, MICRO, STEPS, LR, MAX_NEW = 8, 8, 8, 300, 1e-6, 256
tok = AutoTokenizer.from_pretrained(MODEL); tok.padding_side = "left"
# 权重用 fp32：bf16 存权重配 1e-6 的学习率，更新会被舍入掉
policy = AutoModelForCausalLM.from_pretrained(MODEL, torch_dtype=torch.float32).cuda()
opt = torch.optim.AdamW(policy.parameters(), lr=LR, weight_decay=0.0)
amp = lambda: torch.autocast("cuda", dtype=torch.bfloat16)

def make_task():
    a, b = random.randint(10, 99), random.randint(100, 999)
    msg = [{"role": "user", "content": f"计算 {a}×{b}。先逐步思考，最后把结果写在 <answer></answer> 里。"}]
    return tok.apply_chat_template(msg, tokenize=False, add_generation_prompt=True), str(a * b)

def reward(text, truth):                  # 可验证奖励：答案正确为 1，否则为 0
    m = re.search(r"<answer>\s*(-?\d+)\s*</answer>", text)
    return float(m is not None and m.group(1) == truth)

for step in range(STEPS):
    prompts, truths = zip(*[make_task() for _ in range(BATCH)])
    enc = tok([p for p in prompts for _ in range(G)], return_tensors="pt", padding=True).to("cuda")
    P = enc.input_ids.shape[1]
    with torch.no_grad(), amp():          # rollout：每题 G 个回答
        # 显式关掉模型自带的 top_k / top_p / 重复惩罚，否则采样分布不是 π_θ，训练就成了离策略
        out = policy.generate(**enc, do_sample=True, temperature=1.0, top_p=1.0, top_k=0,
                              repetition_penalty=1.0, max_new_tokens=MAX_NEW,
                              pad_token_id=tok.pad_token_id)
    comp = out[:, P:]
    texts = tok.batch_decode(comp, skip_special_tokens=True)
    r = torch.tensor([reward(t, truths[i // G]) for i, t in enumerate(texts)]).view(BATCH, G)
    adv = ((r - r.mean(1, keepdim=True)) / (r.std(1, keepdim=True) + 1e-4)).view(-1, 1).cuda()
    eos = ((comp == tok.eos_token_id) | (comp == tok.pad_token_id)).int()
    mask = ((eos.cumsum(1) - eos) == 0).float()   # 第一个结束符及其之前的 token 参与损失
    am = torch.cat([enc.attention_mask, torch.ones_like(comp)], 1)
    pos = (am.cumsum(1) - 1).clamp(min=0)         # 左填充时要传位置编号，否则与生成时不一致
    n_tok = mask.sum()
    opt.zero_grad()
    for i in range(0, out.shape[0], MICRO):
        s = slice(i, i + MICRO)
        with amp():
            logits = policy(out[s], attention_mask=am[s], position_ids=pos[s]).logits
        logp = torch.log_softmax(logits[:, P - 1:-1].float(), -1)
        logp = logp.gather(-1, comp[s, :, None]).squeeze(-1)
        # 每批只更新一次，重要性比恒为 1、PPO 的裁剪不起作用，目标就是带组基线的 REINFORCE；
        # 按全批 token 数平均（token 级聚合，见第 3 章）
        loss = -(adv[s] * logp * mask[s]).sum() / n_tok
        loss.backward()
    torch.nn.utils.clip_grad_norm_(policy.parameters(), 1.0)
    opt.step()
    if step % 10 == 0:
        zero = ((r.std(1) == 0).float().mean()).item()
        print(f"step {step} reward {r.mean():.3f} len {mask.sum(1).mean():.0f} zero-var {zero:.2f}")

这段代码刻意省略了参考模型与 KL、每批多次更新与裁剪、价值网络。要做多次更新，就需要保存采样时的 log⁡πold\log\pi_{\text{old}}logπold​ 并加入第 3 章的重要性比与裁剪。HF 的 generate 很慢，放大实验时换成 vLLM 或 SGLang 采样，这时训推不一致就出现了（第 10 章）。

13.4 大模型特有的坑

  • 推理引擎与模型自带的采样参数（top-k、top-p、重复惩罚）会让 rollout 不再是 πθ\pi_\thetaπθ​。
  • 左填充时不传位置编号，训练与生成算出的概率不同。
  • bf16 存权重、10−610^{-6}10−6 学习率：更新被舍入掉，曲线一动不动。
  • 聊天模板、思考标记与最大长度要在训练和评测中保持一致。
  • 截断的回答记 0 分会教模型写短，记负分会教它别冒险。
  • 只报一次采样的 pass@1：方差极大。
  • 随机奖励也能涨分的模型上，结论要谨慎，换一个模型家族复现。
  • 格式奖励过大，模型只学会格式。

14 开放问题

贯穿全篇的问题是：大模型 RL 的许多"技巧"是在补偿离策略、奖励缺陷与评测噪声。去掉这些混杂因素之后，真正起作用的原理还剩多少？

  1. 动作粒度。 token、句子、工具调用还是模型内部的潜在选项？RL 应在训练流水线的哪个阶段介入、占多少算力？
  2. 奖励。 开放任务的奖励能否不依赖另一个大模型？评判被策略针对性优化后还可信吗？验证的成本何时超过生成？
  3. 算法。 critic 何时值得？大词表上合适的信任域是什么？多奖励的权衡能否有原则地设定？
  4. 离线与蒸馏。 在策略蒸馏的收益多少来自在策略、多少来自教师？SFT、蒸馏与 RL 的最优顺序是什么？
  5. 能力边界。 RL 能否发现基座支撑之外的策略？如何在排除污染与提示泄漏后给出可信证据？
  6. 数据与环境。 合成环境的漏洞会教出什么？自我博弈如何不漂移？
  7. 多模态。 RL 改进的是感知还是语言先验？视觉生成的奖励投机能否根治？
  8. 智能体。 昂贵、有状态的环境中如何样本高效？harness 与模型如何共同训练？
  9. 系统。 陈旧度与收敛之间的定量关系？低精度 rollout 的极限？RL 扩展律能否指导资源分配？
  10. 理论。 稀疏、低秩、小 KL 是 RL 的本质，还是因为任务太窄、训练太短？
  11. 安全。 投机能否被检测而不被隐藏？可监控性与能力是否此消彼长？
