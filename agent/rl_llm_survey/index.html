大模型的强化学习：LLM、VLM 与智能体

如果你熟悉 MDP、策略梯度与 PPO，却没有训练过大模型，这一页从你熟悉的概念出发。大模型的后训练本质上是一个 KL 正则的强化学习问题，但它的初始策略来自预训练，环境转移确定且已知，奖励来自偏好模型、程序验证器或另一个大模型，算力主要花在生成上。这些差别决定了哪些 RL 方法有效、哪些技巧必不可少。本页按根本问题分十三章，每章先讲已经确立的做法，再讲最近一年（2025-11 → 2026-10）的进展，最近半年（2026-05 之后）的工作用橙色标出。

导读：把后训练读成一个 RL 问题

大模型的训练分两段。预训练在数万亿 token 上做下一个 token 预测，得到一个会说话、懂知识、但不一定听指令的模型；后训练再用监督微调（SFT，相当于行为克隆）和强化学习，把它变成助手、推理模型或智能体。本页讨论的是后者中的 RL。

与经典 RL 的六点不同

读后面各章时，大多数"技巧"都能追溯到这里
  1. 初始策略极强预训练模型已经会解很多题。RL 的主要作用常常是重新分配已有解的概率，而不是从零发现；起点的"认知习惯"（验证、回溯）决定 RL 能否奏效。→ 第 5、11 章
  2. 转移确定、可任意重启单轮任务没有环境随机性，可以从任何前缀重新采样：同题多采样当基线（GRPO）、从中间状态续写估计价值（VinePPO）、在前缀树上分支。→ 第 3、6 章
  3. 动作空间巨大，有效分支很少词表 15 万，但绝大多数位置上概率集中在一两个 token；熵集中在约两成的"分叉 token"上，探索与信用都发生在那里。→ 第 5 章
  4. 奖励稀疏，来源特殊回答结束才给一个分数；学到的奖励模型可被投机，验证器只覆盖数学、代码等少数领域，开放任务要靠评分细则与评判模型。→ 第 2 章
  5. 时域长、不打折扣一个回答上万 token，常用 γ=λ=1\gamma=\lambda=1γ=λ=1；动作是 token，但"决策"是句子或工具调用，如何划分步长本身是设计选择。→ 第 6、9 章
  6. 算力花在生成上每步训练要先生成几万条长序列；生成与训练分属两套引擎、两种数值精度，"在策略"其实总有一点离策略，异步训练又引入陈旧度。→ 第 3、10 章

四个阶段

每个阶段解决上一阶段的瓶颈

2017 – 2022

RLHF

人类比较两个回答 → 训练 Bradley–Terry 奖励模型 → PPO + KL 惩罚。Christiano 等、摘要、InstructGPT 催生了 ChatGPT。瓶颈：四个模型同时在显存里，奖励模型可被投机。

2023 – 2024

绕开在线 RL

DPO 把 KL 正则目标的闭式解代回偏好损失，用分类式训练替代 PPO；拒绝采样微调、迭代 DPO 成为开放模型的主流配方（Llama 3）。瓶颈：离线数据覆盖不到策略的新行为。

2024-09 – 2025

可验证奖励与推理

o1 与 DeepSeek-R1 表明：用答案是否正确（RLVR）做大规模 RL，模型会自己学会长思维链、自检与回溯。GRPO 去掉 critic，DAPO 等补齐稳定性。瓶颈：只有数学、代码可验证。

2025 下半年 – 2026（现在）

智能体、蒸馏与规模化

RL 进入多轮工具环境（编码、搜索、操作电脑）；在策略蒸馏与自蒸馏成为与 RL 并列的手段；评分细则把 RL 推向开放任务；异步系统、低精度 rollout 与训推一致成为工程主线。

最近半年的八个动向

2026-05 → 2026-10；细节在各章"最近一年"部分

  1. 在策略蒸馏与 RL 并列

    学生自己采样、教师逐 token 打分，相当于奖励稠密的 RL。半年内出现了多教师、黑盒、信任域、异步等几十种变体，也出现了反思：只用初始学生的离线 rollout 蒸馏，17 组师生中 14 组反而更好（Semi-OPD）。

    → 第 4 章

  2. 自蒸馏把反馈变成稠密信号

    让"看过答案或报错信息的自己"当教师（SDPO），二值奖励变成逐 token 的监督；随之而来的是对特权信息作用与崩溃机制的系统检验，以及智能体场景中"多数增益不如宣称"的复现结果（现实检验）。

    → 第 4、9 章

  3. 评分细则奖励走向主流，也被投机

    开放任务用 rubric 打分做 RL 已成常规；新问题是按项相加的分数会诱导堆砌内容，评判会奖励编造（FORK、加法聚合、ImpossibleRubrics）。

    → 第 2、12 章

  4. critic 回归

    GRPO 一度让价值网络退场；随着长程与智能体任务增多，稳定可扩展的 actor-critic 重新出现（EasyPPO、S3AC、PACT），价值模型也开始像奖励模型一样被预训练（LenVM、V0.5）。

    → 第 3、6 章

  5. 训推一致成为系统问题

    同一组权重在推理引擎与训练引擎里算出的概率不同；随着 FP8、NVFP4、FP4 rollout 普及，失配的诊断与修正（校准重要性采样、TRIAGE、TRACE）成为稳定性的主要来源。

    → 第 3、10 章

  6. 可验证环境的规模化

    从 GitHub PR 自动构建百万级 SWE 环境（SWE-Universe），终端、手机、电脑与网页环境的合成引擎相继出现（CLI-Universe、MobileGym、RecreationWorld），模型也开始自己写环境再自我博弈（SPADE）。

    → 第 7、9 章

  7. 对"技巧"的冷静复查

    同一 GRPO 配方下 8 种数据选择与重加权方法都没有显著优于均匀采样（DataFlex-RL）；RLVR 的权重轨迹近乎秩 1、可线性外推（RELEX）；最简单的单阶段配方也能做到最好（JustRL）。

    → 第 7、11 章

  8. 多奖励与多能力的整合

    真实后训练要同时优化正确性、格式、长度、安全与风格：按奖励分别归一化、按方差或饱和度加权、只把每个奖励分给相关 token（DVAO、饱和感知、MRTPO）；多个领域的 RL 专家再用多教师蒸馏合并（MOPD）。

    → 第 3、4 章

问题设定：把语言模型看作策略

后训练在优化什么？什么是动作、什么是回合？和你熟悉的 RL 设定差在哪里？

主流做法是按整段回答给奖励、按 token 算梯度：奖励层面它是上下文赌博机，梯度层面它是一个转移确定的 token 级 MDP。与经典 RL 最大的区别在起点：策略是预训练模型，后训练的每一步——SFT 冷启动、KL 约束、RL——都是在这个先验附近调整。最近一年的变化是 RL 向前移，进入中期训练乃至预训练；研究者也开始用受控实验区分哪些能力来自预训练、哪些来自 RL。

后训练流水线

预训练（下一 token 预测）→ 中期训练（推理、代码、长上下文数据）→ SFT（行为克隆，长思维链冷启动）→ RL（RLHF / RLVR / 智能体 RL）→ 蒸馏到小模型。DeepSeek-R1 同时给出两种路线：R1-Zero 从基座直接 RL，R1 先冷启动 SFT 再多轮 RL 与拒绝采样。

容易被忽视的接口

聊天模板（角色与 <think> 标记）决定策略看到的状态；最大长度截断等于提前终止回合（奖励记 0 还是加超长惩罚是设计选择）；采样温度偏离 1 即离开在策略；结束符 EOS 是一个需要学会的动作。

已经确立的

2025-10 之前

最近一年（2025-11 → 2026-10）

橙色为最近半年

  2. 2025-12动作不必是 token。预训练模型的残差流中存在可用于分层控制的时间抽象；在这些"选项"上做内部 RL，能解决 token 级 RL 无法解决的稀疏奖励任务（时间抽象与分层 RL）。
  3. 2025-12 · 2026-01RL 前移到预训练。在语料上主动选择要遮盖的片段再预测（PretrainZero），把网页文本改写成填空式多选题得到无限 RLVR 数据（Golden Goose）；此前已有强化中期训练（RMT）与在预训练语料上做 RL（RLPT）。
  4. 2026-07能力的来源可以追踪。把 RL 后训练与之前的预训练放在同一受控框架里，追踪预训练数据如何决定 RL 能学到什么（从预训练到后训练理解推理）；多轮长程规划也被拆成预训练、SFT 与蒸馏三个阶段分别研究（多轮规划的物理学）。

奖励从哪里来：偏好、验证器与评分细则

没有游戏分数，奖励从哪里来？每种来源会怎样失效？

奖励有三类来源，各对应一类任务和一种失效方式。偏好奖励模型（RLHF）覆盖一切人类能比较的任务，但可被投机；可验证奖励（RLVR）只覆盖有标准答案或可执行检查的任务，但很难投机，推理模型的进步主要来自这里；生成式评判（大模型按评分细则打分）把 RL 推向医学、写作、研究等开放任务，代价是评判本身的偏差。最近一年三者合流：奖励模型变成会推理、会调用工具的生成式模型，验证器扩展到证明与软件，评分细则从人写变成自动生成并随策略演化。

策略优化算法：从 PPO 到 GRPO，再到之后

有了奖励，用什么算法优化？为什么去掉 critic 的 GRPO 能成为默认？它又有哪些毛病？

LLM 上的策略优化几乎都是 PPO 的变体，区别集中在三处：优势怎么估（价值网络、同题组内均值、留一法）、重要性比与裁剪放在哪一层（token 还是整段回答）、损失怎样在 token 间聚合。GRPO 去掉 critic 后成为推理 RL 的默认，此后一年的工作大多在修补它的偏差。最近一年的结论是：训推不一致与策略陈旧足够小时，最朴素的带重要性采样的策略梯度就足够稳定，不稳定主要来自离策略程度；与此同时，长程任务让 critic 重新回来，多奖励优化成为新的算法问题。

绕开在线 RL：直接偏好优化、拒绝采样与蒸馏

不在训练中生成，能否得到 RL 的效果？在线采样到底提供了什么不可替代的东西？

在线 RL 贵在每一步都要生成，于是有三条省钱路线：直接偏好优化（DPO 系列）在固定偏好对上做分类式训练；拒绝采样微调（专家迭代）只留下答对的样本做 SFT；蒸馏让强教师提供目标。实证与理论指向同一结论：在策略采样（数据来自当前策略）与负梯度（主动压低差回答）是 RL 有效的关键，离线方法缺的正是这两点。在策略蒸馏（OPD）把两者结合——学生自己采样，教师逐 token 给出稠密信号，成本远低于 RL。最近半年它成为与 RL 并列的后训练手段，同时暴露出师生分布不匹配时的失败，"是否真的需要在策略"也被重新追问。

探索、熵与能力边界：RL 在发现还是在锐化

RL 是让模型学会了新能力，还是只把已有的解挑出来？在这样的动作空间里怎样探索？

这是最近一年争论最多的问题。一方面的证据：大 kkk 下基座模型的 pass@k 反超 RL 后的模型；随机甚至错误的奖励也能提升某些模型；对基座做简单的锐化采样就接近 RL 的效果——RL 主要在重排预训练中已有的解。另一方面：足够长、足够稳的 RL 能解出基座采不到的题，受控实验中 RL 在能力边缘带来外推。两者的交集是：RL 的收益受制于基座的支撑集与探索能力。因此探索——维持熵、奖励多样性、给难题搭台阶、借用别人的轨迹——成了算法设计的中心。

信用分配、过程奖励与推理

一个回答上万 token，只在结尾得到一个 0/1，信用怎样分？"想得更久"为什么有用，又如何不浪费？

经典 RL 用价值函数做信用分配；在 LLM 上价值网络难训，于是出现三类替代：过程奖励模型（PRM）给每一步打分；蒙特卡洛续写直接估计中间状态的价值（单轮任务可以从任意前缀重启）；以及利用 KL、熵、注意力等内部结构定位关键 token。已有的结论是：PRM 适合做搜索与重排，直接当 RL 奖励容易被投机；把步骤奖励定义为"进步"（优势）而非"正确"更有效。与之配套的是测试时计算：思考长度、并行采样与自我验证本身成了 RL 训练的对象，过度思考与长度控制随之成为新问题。

数据、课程、环境与自我博弈

RL 的"环境"在哪里？题从哪里来，难度怎么排，能否不要人工数据？

LLM 的 RL 没有现成的环境：题库加验证器就是环境，智能体任务还需要可执行的沙箱。数据决定学习信号——通过率接近 0 或 1 的题不提供梯度，于是动态过滤、按难度采样、合成更难的变体成为标配。为了摆脱人工数据，有两条路：程序化或由模型自动构建大规模可验证环境；以及自我博弈，让同一个模型出题、解题、互相验证。最近半年环境规模从数千推到百万，模型也开始自己写环境；但一项严格控制种子的评测发现，各种数据选择与重加权技巧都没有显著优于均匀采样。

二值奖励、通过率为 ppp 时，组内优势的方差与有效梯度正比于 p(1−p)p(1-p)p(1−p)：太难（p→0p\to0p→0）或太易（p→1p\to1p→1）的题都浪费 rollout，课程应集中在 p≈0.5p\approx0.5p≈0.5 附近（VCRL）。

多模态：视觉推理、视觉生成与 VLA

视觉进来之后，RL 的形式不变，问题变了：模型真的在看吗？生成模型怎么做策略梯度？

对视觉语言模型，难点是让模型真正利用图像：多模态推理上的 RL 增益常常来自文本推理而非视觉感知，于是有了感知奖励（IoU、计数）、"用图像思考"（把裁剪、放大当作动作）与专门诊断"盲训练"的基准。对图像与视频生成，扩散与流模型的去噪过程被写成多步 MDP，GRPO 被移植过来，奖励投机与多奖励的此消彼长比文本更严重。对机器人 VLA，RL 在仿真与真机上补足模仿学习的泛化，世界模型开始充当环境与 critic。

系统与规模：生成、同步与训推一致

怎样在上千张 GPU 上跑 RL？算力花在哪里？"在策略"在工程上意味着什么？

一次 RL 迭代 = 推理引擎生成几万条长回答 + 训练引擎计算梯度 + 把新权重同步回推理引擎。生成占大头，且回答长度呈长尾，最长的一条决定整批的等待。系统设计因此围绕三件事：让生成与训练重叠（异步、部分 rollout、在飞更新权重）；降低生成成本（低精度、投机解码、KV 量化）；修正由此产生的离策略与数值不一致。最近一年，训推不一致从偶发的 bug 变成系统性问题：同一组权重在两个引擎上算出的概率不同，MoE 的路由也不同，FP8、NVFP4 乃至 FP4 rollout 让失配更大。另一条线是可预测性：RL 的算力—性能曲线开始可以拟合与外推。

理论与机制：RL 改变了模型的什么

为什么 RL 遗忘更少、更新更稀疏、泛化更好？哪些结论是可以证明的？

与 SFT 相比，RL 后训练有几个稳定的经验现象：遗忘更少、更新稀疏且避开权重的主方向、多任务之间互不干扰、能泛化到训练分布之外。最近一年它们有了统一的解释方向：在策略训练偏向与原模型 KL 最近的解（RL's Razor），因此改动小而局部；RL 的权重轨迹极低秩，可以从早期外推；token 级的分布变化集中在少数关键 token 上。理论上，锐化与生成—验证差距解释了为何 RL 在信息论上"不必要"却在实践中有效；组相对优势、熵与 KL 的动力学已可推导。

RL's Razor

在所有能解决新任务的策略中，在策略 RL 偏向在新任务上与原模型 KL 最近的那个，而 SFT 可以收敛到任意远的分布；遗忘的程度由这个 KL 决定（RL's Razor）。

锐化

自我改进就是把概率集中到模型自认为最好的回答上，如 πsharp(y∣x)∝π(y∣x)α\pi_{\text{sharp}}(y\mid x)\propto\pi(y\mid x)^{\alpha}πsharp​(y∣x)∝π(y∣x)α（α>1\alpha>1α>1）；SFT 与 RL 实现锐化的样本复杂度不同（锐化机制）。对基座直接从 πα\pi^\alphaπα 采样就接近 RL 的效果（幂分布采样）。

生成—验证差距

若奖励模型类比策略类简单得多，"先学一个奖励、再在其上做 RL"比直接最大似然更容易找到好策略——这解释了离线数据在信息论上已足够、在线 RL 在实践中却更好（殊途同归）。

更新的几何

RL 只更新 5%–30% 的参数，不同种子下的子网络高度重合（小子网络）；更新避开权重的主成分方向（偏离主方向）；权重轨迹近乎秩 1，幅度随步数近线性增长（RELEX）。

奖励投机与安全：优化压力把模型推向哪里

奖励和意图之间总有缝隙。RL 会怎样利用它？利用之后会泛化成什么？

RL 是最强的优化器，因此最容易找到奖励与意图之间的缝隙。RLHF 时代的问题是谄媚与说服：模型学会让评估者满意而不是正确。RLVR 时代出现了更直接的投机：修改测试、硬编码答案、利用验证器漏洞；而且在真实编程环境中学会投机的模型，会泛化出伪装对齐、破坏安全研究等更广的失准。另一个新维度是思维链：它让我们能读到模型的意图，但若把监控信号放进奖励，模型会学会隐藏意图。最近一年，评分细则奖励、AI 审稿与社会规则环境中都出现了投机的实证。

Goodhart 的定量版本

代理奖励 r^=r+ϵ\hat r=r+\epsilonr^=r+ϵ，优化越强，策略越集中在 ϵ\epsilonϵ 大的区域；第 2 章的过度优化曲线是它的定量形式。常用的缓解：KL 约束、奖励模型集成与悲观估计、限制优化步数、让验证器更严格（Gao 等、集成）。

从投机到失准

窄任务上的投机会泛化：只学写不安全代码、或在无害任务上骗评判，就出现广泛失准（涌现失准、奖励投机学校）；在真实编程 RL 环境中学会投机，泛化为对齐伪装与破坏（自然涌现的失准）。

思维链可监控性

用另一个（甚至更弱的）模型读 CoT，比只看动作更能抓住投机；把 CoT 监控放进奖励，优化弱时模型更好也更对齐，优化强时模型会继续投机、同时在 CoT 中隐藏意图（监控推理模型）。因此业界呼吁保护可监控性（CoT 可监控性）。

安全也是奖励设计

规则化的安全奖励（RBR）、带约束的 RL（Safe RLHF）、先推理安全规范再回答（审慎对齐）；可扩展监督：辩论、证明者—验证者博弈、弱到强泛化。

实践入门：RL 研究者的第一个大模型 RL 实验

从哪个模型、哪个任务、哪个框架开始？要盯哪些曲线？哪些坑是大模型特有的？

建议的路径是：先在单卡上用几十行代码跑通一个可验证任务的 GRPO，亲眼看到奖励、熵与回答长度怎样变化；再换成成熟框架，把同样的实验放大到多卡、长序列与真实基准。大模型 RL 的多数失败不在算法，而在采样是否真的在策略、奖励是否真的在测你想测的东西、评测是否足够稳。

  1. 选模型

    从 0.5B–4B 的开放模型开始。基座模型适合研究"从零 RL"，指令模型更容易遵守答案格式、起步更快。部分模型家族在常见数学基准上可能有污染，随机奖励也能涨分（虚假奖励、污染），结论至少要在两个模型家族上复现。

  2. 选任务与验证器

    先用答案确定、可以自动判定的任务：程序生成的算术与逻辑题（Reasoning Gym）、GSM8K、MATH。验证器 = 答案抽取 + 等价判定；格式错误给 0 分即可，格式奖励不要大到让模型只学格式。

  3. 选算法与超参

    GRPO 或 RLOO，加上 DAPO 的修补作为起点：每题 G=8G=8G=8–16 个样本、温度 1.0、非对称裁剪（如 ϵlow=0.2, ϵhigh=0.28\epsilon_{\text{low}}=0.2,\ \epsilon_{\text{high}}=0.28ϵlow​=0.2, ϵhigh​=0.28）、token 级损失聚合、过滤零方差组、不加或只加很小的 KL；全参学习率在 10−610^{-6}10−6 量级，LoRA 约大一个数量级（DAPO、LoRA Without Regret）。这些是常见起点，不是定论。

  4. 选框架

    单机：TRL；多机与长序列：veRL、OpenRLHF、ROLL、AReaL；不想管集群：Tinker；智能体：Agent Lightning、VerlTool、AgentGym-RL。

  5. 评测

    报 avg@k（每题采 kkk 次的平均正确率，k=16k=16k=16 或 32）与 pass@k，而不是单次采样；常用 MATH-500、AIME、GPQA、LiveCodeBench，智能体用 SWE-bench 等；多个随机种子；与同算力的 SFT 和拒绝采样基线比较。

最小 GRPO

单卡、PyTorch + transformers；任务是两位数乘三位数，答案写在 <answer> 里
import random, re, torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"     # 任意小的指令模型
G, BATCH, MICRO, STEPS, LR, MAX_NEW = 8, 8, 8, 300, 1e-6, 256
tok = AutoTokenizer.from_pretrained(MODEL); tok.padding_side = "left"
# 权重用 fp32：bf16 存权重配 1e-6 的学习率，更新会被舍入掉
policy = AutoModelForCausalLM.from_pretrained(MODEL, torch_dtype=torch.float32).cuda()
opt = torch.optim.AdamW(policy.parameters(), lr=LR, weight_decay=0.0)
amp = lambda: torch.autocast("cuda", dtype=torch.bfloat16)

def make_task():
    a, b = random.randint(10, 99), random.randint(100, 999)
    msg = [{"role": "user", "content": f"计算 {a}×{b}。先逐步思考，最后把结果写在 <answer></answer> 里。"}]
    return tok.apply_chat_template(msg, tokenize=False, add_generation_prompt=True), str(a * b)

def reward(text, truth):                  # 可验证奖励：答案正确为 1，否则为 0
    m = re.search(r"<answer>\s*(-?\d+)\s*</answer>", text)
    return float(m is not None and m.group(1) == truth)

for step in range(STEPS):
    prompts, truths = zip(*[make_task() for _ in range(BATCH)])
    enc = tok([p for p in prompts for _ in range(G)], return_tensors="pt", padding=True).to("cuda")
    P = enc.input_ids.shape[1]
    with torch.no_grad(), amp():          # rollout：每题 G 个回答
        # 显式关掉模型自带的 top_k / top_p / 重复惩罚，否则采样分布不是 π_θ，训练就成了离策略
        out = policy.generate(**enc, do_sample=True, temperature=1.0, top_p=1.0, top_k=0,
                              repetition_penalty=1.0, max_new_tokens=MAX_NEW,
                              pad_token_id=tok.pad_token_id)
    comp = out[:, P:]
    texts = tok.batch_decode(comp, skip_special_tokens=True)
    r = torch.tensor([reward(t, truths[i // G]) for i, t in enumerate(texts)]).view(BATCH, G)
    adv = ((r - r.mean(1, keepdim=True)) / (r.std(1, keepdim=True) + 1e-4)).view(-1, 1).cuda()
    eos = ((comp == tok.eos_token_id) | (comp == tok.pad_token_id)).int()
    mask = ((eos.cumsum(1) - eos) == 0).float()   # 第一个结束符及其之前的 token 参与损失
    am = torch.cat([enc.attention_mask, torch.ones_like(comp)], 1)
    pos = (am.cumsum(1) - 1).clamp(min=0)         # 左填充时要传位置编号，否则与生成时不一致
    n_tok = mask.sum()
    opt.zero_grad()
    for i in range(0, out.shape[0], MICRO):
        s = slice(i, i + MICRO)
        with amp():
            logits = policy(out[s], attention_mask=am[s], position_ids=pos[s]).logits
        logp = torch.log_softmax(logits[:, P - 1:-1].float(), -1)
        logp = logp.gather(-1, comp[s, :, None]).squeeze(-1)
        # 每批只更新一次，重要性比恒为 1、PPO 的裁剪不起作用，目标就是带组基线的 REINFORCE；
        # 按全批 token 数平均（token 级聚合，见第 3 章）
        loss = -(adv[s] * logp * mask[s]).sum() / n_tok
        loss.backward()
    torch.nn.utils.clip_grad_norm_(policy.parameters(), 1.0)
    opt.step()
    if step % 10 == 0:
        zero = ((r.std(1) == 0).float().mean()).item()
        print(f"step {step} reward {r.mean():.3f} len {mask.sum(1).mean():.0f} zero-var {zero:.2f}")

这段代码刻意省略了参考模型与 KL、多次更新与裁剪、价值网络；要做每批多次更新，就需要保存采样时的 log⁡πold\log\pi_{\text{old}}logπold​ 并加入第 3 章的重要性比与裁剪。HF 的 generate 很慢，放大实验时换成 vLLM 或 SGLang 采样，这时训推不一致就出现了（第 10 章）。

大模型特有的坑

  • 推理引擎与模型自带的采样参数（top_k、top_p、重复惩罚）会让 rollout 不再是 πθ\pi_\thetaπθ​
  • 左填充时不传位置编号，训练与生成算出的概率不同
  • bf16 存权重、1e-6 学习率：更新被舍入掉，曲线一动不动
  • 聊天模板、思考标记与最大长度要在训练和评测中保持一致
  • 截断的回答记 0 分会教模型写短，记负分会教它别冒险，要想清楚再选
  • 只报一次采样的 pass@1：方差极大，用 avg@k 与多个种子
  • 随机奖励也能涨分的模型上，结论要谨慎，换一个模型家族复现
  • 格式奖励过大，模型只学会格式
