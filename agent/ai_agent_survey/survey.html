AI 智能体：应用、实践与最近半年的动向

长文版。数据截至 2026-10-30；论文与资源库 1100 条（1027 条 arXiv 已用官方 API 核验标题与日期），其中最近一年（2025-11 →）789 条、最近半年（2026-05 →）600 条。本文重应用与实践：每章先讲已经成形的做法与代表工作，再讲最近半年的变化，最后给出实践要点与开放问题；第 12 章是一份可以照着做的入门指南，附录 A 按月整理最近半年的动向，附录 B 是全部条目的总表。正文中的数字摘自论文摘要或官方发布，设置各不相同，不可横向比较；最近半年的多数工作是尚未经过同行评审的预印本。本文不覆盖机器人与具身智能体。

0 导读

0.1 什么是智能体

本文采用工程上最常用的定义：智能体是在循环中使用工具、根据环境反馈自主决定下一步的模型系统。它由四部分组成：

  • 模型：读入目标与上下文，决定下一步做什么（思考、调用哪个工具、何时结束）。
  • 工具：把模型的决定变成对外部世界的动作，如读写文件、运行命令、搜索网页、点击屏幕、调用业务 API。
  • 循环：把动作的结果（观察）送回模型，直到任务完成、失败或需要人确认。
  • harness：包住模型的全部程序，决定模型能看到什么（上下文）、能做什么（工具与权限）、什么时候停（预算与停止条件），以及出错时怎么恢复。

这个"思考—行动—观察"的循环最早由 ReAct 写成。今天的编码智能体、计算机使用智能体和深度研究智能体仍然是它，只是工具更多、循环更长、上下文管理更讲究。一个重要的经验是：在模型能力相近时，智能体好不好用主要取决于工具、上下文与 harness。

0.2 从一次调用到自主智能体

Anthropic 的 Building effective agents 给出了一条被广泛接受的原则：先用能解决问题的最简单方案。按自主程度，可以分成四档：

形态 谁决定步骤 适合 代价
单次调用 无步骤 分类、抽取、摘要、问答 最便宜，最好评测
工作流 代码 链式、路由、并行、评审—修改；步骤可预知 可控，但不灵活
智能体 模型 编码、研究、操作电脑；步数与路径事先不知道 成本与风险随步数增长
多智能体 / 长时运行 多个模型 可并行拆分的宽任务；跨会话持续数小时到数天 token 开销大，协作易出错

0.3 四个阶段

2022 → 2023：范式成形。ReAct、Toolformer、Reflexion、Generative Agents、Voyager 提出了循环、工具学习、自我反思、记忆与技能库等基本概念；AutoGen、MetaGPT 等多智能体框架流行。这一阶段的智能体主要靠提示词实现，在真实任务上很不可靠。

2024：进入真实环境。SWE-bench、OSWorld、WebArena 把评测放进真实仓库、操作系统与网站；SWE-agent 提出"智能体—计算机接口"，Agentless 提醒简单流水线也很强；年底出现了 Claude 计算机使用、MCP 与 Building effective agents。

2025 → 2026-04：产品化与智能体模型。Deep Research、Claude Code、Codex、ChatGPT agent 成为日常工具；模型开始为智能体专门训练（Kimi K2、GLM-4.5、Tongyi DeepResearch）；工程上出现了上下文工程（Anthropic、Manus）、AGENTS.md、Agent Skills；开源自托管的个人智能体 OpenClaw 走红；2025-12 成立 Agentic AI Foundation；2026-04 出现托管的 Claude Managed Agents。

2026-05 → 2026-10（最近半年）：harness 时代。harness 与技能成为研究和工程的主战场，并开始自我演化；协议层收敛（MCP 无状态化、A2A 加入 AAIF、AAIF 扩展到十个项目）；托管智能体普及；任务从分钟级走向天级；训练转向合成环境与大规模智能体 RL；评测走向真实工作与经济价值；安全从防注入走向系统层。

0.4 最近半年的八个动向

  1. Harness 成为一等公民，并开始自己改自己。同一个模型换一个 harness，成绩差异很大（StateM）；于是 harness 本身成为优化对象：轨迹回放、递归自我改进、与权重联合训练。也有工作提醒"改了不等于变好"（更新 harness 不等于 harness 有益、RRSI）。见第 3、5、9 章。
  2. 技能从文件格式变成生态。技能进入 AAIF；研究转向技能的自动生成、演化、跨 harness 迁移与内化进权重；同时出现技能后门（SkillJack）与水印（SkillMarker）。见第 3、11 章。
  3. 协议层收敛，托管智能体普及。MCP 2026-07-28 版改为无状态；A2A 1.0 加入 AAIF；Claude、Gemini、OpenAI 都提供了托管的"循环 + 沙箱"。见第 4 章。
  4. 从分钟到天。多日自主开发（Harness-of-Harness）、超长程执行（Marathoner）成为目标；上下文管理转向"让模型自己决定忘记什么"；METR 的时间视野测量在超过 16 小时后已不可靠（METR）。见第 2、5、10 章。
  5. 训练：合成环境 + 智能体 RL 规模化。终端、软件、桌面、办公协作环境被大规模合成；在策略蒸馏的各种变体与现实检验；万亿参数级的智能体 RL（NeMo-DCR）；训练开始面向"模型 + harness"整体（Harness Scaling）。见第 9 章。
  6. 常驻的个人智能体与主动性。OpenClaw 带出了一批"Claw 类"系统、基准与安全工作；主动式智能体有了分层定义与训练环境（主动式智能体基础）。见第 2、8、11 章。
  7. 评测走向真实工作与经济价值。Agents' Last Exam、OSWorld 2.0、BizBench、Business Arena；同时反思污染、预测效度与评测成本。见第 10 章。
  8. 安全从防注入走向系统层。智能体操作系统（AgentKernel）、事务式执行（Agentic Transaction）、撤销能力（UndoBench）、欺骗与越界行为评测。见第 11 章。

1 构件：模型、工具与智能体循环

1.1 函数调用是一切的基础

今天的智能体建立在函数调用之上：开发者用 JSON Schema 描述每个工具的名称、用途和参数；模型在需要时输出结构化的调用；宿主程序执行后把结果作为观察放回对话。一轮可以并行发出多个调用，宿主把全部结果放进下一条消息。出错时把错误作为结果返回（而不是中断循环），模型通常能自己纠正。

这一形态由三条早期路线汇成：

  • 推理与行动交替：ReAct 让模型交替输出思考与动作；更早的 WebGPT 让模型使用文本浏览器并引用来源，MRKL 把 LLM 作为路由器连接外部模块。
  • 学会使用工具：Toolformer 让模型自监督地学会何时调用 API；Gorilla 用检索减少 API 幻觉；ToolLLM 构造了覆盖一万多个真实 API 的数据；HuggingGPT 让 LLM 调度专家模型；LLM as Tool Makers 与 CRAFT 让模型自己制造工具。
  • 代码即动作：PAL 把推理写成程序；CodeAct 发现以 Python 作为统一动作空间优于 JSON 工具调用；DynaSaur 让智能体用代码动态生成新动作。LLM-in-Sandbox 进一步发现，仅仅让模型在代码沙箱中探索就能激发通用的智能体能力。

1.2 规划、反思与推理模型

2023 年的大量工作用提示实现规划与反思：Reflexion（语言化的自我反思）、Self-Refine、Tree of Thoughts、LATS（蒙特卡洛树搜索）、Plan-and-Solve；效率方向有 ReWOO（先规划全部调用）与 LLMCompiler（把调用编译为可并行的 DAG）。

推理模型出现后，这些能力大部分被内化：模型在工具调用之间继续思考（交错思考），自己决定是否需要计划和回溯。新的问题变成"想多少"：过度思考在智能体任务中会损害表现；智能体的测试时扩展与 预算感知的工具使用研究如何把计算花在刀刃上。2025 年起，工具使用越来越多地由强化学习直接训练（ReTool、ToolRL、ARTIST），而不是靠提示。API 智能体与 GUI 智能体的分化与融合，则是第 5、6 章的背景。

1.3 最近半年

  • 打破"想—做—看"的顺序。Second Thought（2026-08）在执行动作、等待观察的同时并行推理；LLM 是通用的异步智能体（2026-09）让模型边想边做，减少等待工具返回造成的空转。
  • 长程失败的细致刻画。DeLoop 发现长程智能体常重复做过的工作，并把重复动作当作自监督信号；Interlock 研究为什么每一步局部正确却完不成整体任务；Agent-Reflex 只在关键步骤前反思；工具使用智能体如何失败分析改变外部状态（写数据库、发消息）时的失败模式。
  • 主动性。主动式智能体基础提出主动性的分层与 Proactivity-Gym，横向与纵向主动性区分"多做相关的事"与"把事做深"。
  • 长程规划的机制。多轮长程规划的物理学从预训练到后训练追踪规划能力的来源；循环语言模型在组合式工具调用上泛化更好；EVOKE 激发模型的世界知识用于多步决策。
  • 工具使用数据来自合成环境。EnvFactory、WEFT、DART-SD、无环境 API 数据合成，详见第 9 章。

1.4 实践要点与开放问题

实践上：工具要少而精、职责不重叠，描述写给"第一次见到它的新同事"；出错返回可读的错误；设置最大步数、超时与花费上限；无依赖的调用并行；步骤可预知时用代码写成工作流，只在需要判断的地方调用模型。

开放问题：何时先规划、何时直接行动？如何可靠地检测"原地打转"？异步、并行行动下，如何保证对外部状态的修改正确且可回滚？

2 上下文工程与记忆

2.1 上下文是唯一的工作记忆

模型每一步只能看到上下文窗口里的内容，而有效容量远小于标称长度：信息越多，越容易遗漏关键约束、被无关内容分心。上下文工程就是在每一步决定放进什么（Effective context engineering）。可以概括为四种操作：

  • 写：把计划、进度、中间结果写到文件或笔记里，需要时再读。
  • 选：只在需要时检索（"即时"检索），而不是预先把资料塞满上下文。
  • 压：接近上限时摘要旧轮次、清掉过时的工具输出。
  • 隔：把探索性的子任务交给子智能体，它们在独立上下文中工作，只把结论交回。

2.2 为缓存而设计

长轨迹智能体的输入 token 远多于输出 token，KV 缓存命中率是头号成本指标。Manus 的经验：前缀保持稳定（系统提示与工具列表不要频繁变动），历史只追加不修改，时间戳等易变内容放在后面；保留错误轨迹让模型从中学习；用不断重写的待办清单把目标"复述"到上下文末尾。Cache Engineering for Agents（2026-10）系统地研究了上下文布局与缓存命中、成本的关系。

2.3 状态外化与长期记忆

MemGPT 最早把上下文窗口类比为内存、外部存储类比为磁盘；Generative Agents 的"记忆流 + 反思 + 检索"奠定了智能体记忆的基本结构。长程任务中，ReSum、AgentFold、IterResearch 定期把历史重建为精简状态；FS-Researcher 直接把文件系统当作工作记忆。

长期记忆按内容可分为情节记忆（发生过什么）、语义记忆（事实与偏好）和程序性记忆（怎么做）。程序性记忆的代表是 Agent Workflow Memory、Memp；ACE 把上下文当作不断演化的"剧本"，它进一步沉淀就是第 3 章的技能。产品化的记忆层有 Mem0（论文）与 Letta；GAM 主张用深度研究式的即时检索代替静态记忆；MemEvolve、MemSkill 让记忆系统自身演化。综述见 AI 智能体时代的记忆。

2.4 最近半年

  • 记忆要算净价值。Memory Tax（2026-10）在多个基准与模型上发现，许多专门的记忆系统在不少情况下不如直接对原始历史做检索，即净价值为负，并把收益与"记忆税"分开度量；朴素 RAG 比想象中强（2026-10）在 LoCoMo、LongMemEval 等基准的七个设置中有六个排名第一；预注册实验 选择取代提取显示选对原始对话轮次往往就够。
  • 让模型自己管理上下文。自压缩智能体、ContextPilot（细粒度 RL）、AutoMem（把记忆当作可学习的技能）。
  • 长程状态的新表示。显式信念状态、FlowState（以执行状态为记忆）、CarryOn（面向对象的上下文）、PARSER（并行阅读）。
  • 记忆是重建而非回放。图记忆、MemHarness。
  • 失效、交接与个性化。STALE（发现记忆过期）、SubtleMemory（OpenClaw 类个人智能体）、交接税（接手他人轨迹时表现下降）、先个性化再存储、HABIT-Bench（从弱证据归纳用户习惯）。
  • 以记忆实现持续学习。以记忆为中心的持续学习、可组合的持续学习机制、智能体上下文管理。

2.5 实践要点与开放问题

实践上：稳定前缀、只追加历史、监控缓存命中率；工具输出截断或分页，大文件按需读取；长任务维护进度文件与待办清单；上长期记忆之前先用"原始对话 + 朴素检索"做基线；为记忆设更新与过期机制。

开放问题：压缩时丢掉什么、如何保证不丢关键约束？多用户、多智能体共享记忆的权限与隐私（GateMem）；记忆中的谄媚与污染（MemSyco-Bench）。

3 Harness、技能与多智能体

3.1 Harness：包住模型的程序

harness 包括系统提示、工具集、权限、上下文策略、子智能体、钩子、验证与重试。SWE-agent 的"智能体—计算机接口"（ACI）最早表明：为智能体专门设计查看、搜索、编辑命令，比直接给它人用的 shell 更有效。Anthropic 的长时运行 harness给出另一组经验：第一个会话负责初始化环境、写好功能清单与进度文件；之后每个会话读进度、推进一个功能、测试、提交，保证下一个会话能接手。

harness 的分量有多大？StateM（2026-08）不改模型权重，只把执行组织成持久状态、分阶段上下文和可检查的状态转移，就把同一模型在 Terminal-Bench 2.1 上从 83.1% 提到 92.1%（标题中的 95.3% 是其报告的最高原始准确率）。编码 harness 设计的实证研究拆解了哪些设计决定长程表现。

3.2 技能与项目上下文文件

技能是一个文件夹：SKILL.md 写明用途与步骤，可附带脚本与资源。关键是渐进披露：上下文里只放每个技能的名称和一句描述，任务相关时才读入全文，需要时再执行脚本（Agent Skills、开放格式、官方示例）。思想可追溯到 Voyager 的可执行技能库。AGENTS.md（以及 CLAUDE.md 等）写构建命令、代码风格、测试方法和禁区（AGENTS.md）；Agent READMEs 分析了这类文件在真实仓库中的内容与演化。

技能研究在 2025 年底到 2026 年初快速增长：带技能库的 RL、SkillRL、SkillNet、Trace2Skill、Memento-Skills、SkillClaw；评测有 SkillsBench 与野外的智能体技能。LLM 智能体中的外化把记忆、技能、协议与 harness 统一看作"把能力外化到模型之外"。

3.3 多智能体：何时值得

主流模式是编排者—工人：主智能体拆分任务、并行派出子智能体、汇总结果。Anthropic 的多智能体研究系统在需要广泛搜索的任务上明显优于单智能体，但 token 用量约为普通聊天的 15 倍，因此只适合价值高、可并行的任务。Don't Build Multi-Agents 从反面论证：子智能体之间缺少共享上下文，容易做出互相冲突的决定；MAST 给出了多智能体系统的失败分类。早期框架包括 CAMEL、ChatDev、MetaGPT、AutoGen、AgentVerse 与多智能体辩论；后来转向可训练的组织：AgentFlow、Chain-of-Agents、智能体组织、AOrchestra、递归多智能体。

3.4 最近半年

这是本文收录最密集的方向（约 90 条）。

  • harness 自动优化与递归自我改进。从轨迹回放中改进（回顾式 harness 优化、Continual Harness、AutoSaddler），到递归自我改进（递归 harness 自我改进、HarnessDev、ModularRSI、Harness²）、自然选择（DarwinX）和兼顾成本的帕累托优化（HarnessPro）；Raven 做跨领域复用的"harness 的 harness"，Harness Handbook 让不断演化的 harness 保持可读。
  • "改了"不等于"变好"。更新 harness 不等于 harness 有益把"能改"与"改得有益"分开评测；RRSI 用正则化防止 harness 过拟合；CoEvo-RSI 讨论模型与 harness 协同演化时的问题。
  • harness 与权重的边界移动。Harness-Zero 把 harness 能力蒸馏进模型；WHALE 联合优化 harness 与权重；测试时 AI4AI 通过 harness 把强模型的能力迁移给弱模型。
  • 技能的生成、优化、迁移与内化。模型生成技能的系统研究与揭秘智能体技能回答技能何时有效、何时失效；SkillOpt、SkillGrad、SkillForge 优化技能；从代码大规模合成技能、Repo-To-Skill、COLLEAGUE.SKILL 批量生产技能；跨 harness 技能优化研究迁移；Skill0.5、LatentSkill 把技能内化进权重；SkillsVote 管理技能生命周期；SkillZip 压缩技能库。
  • 多智能体规模化与可学习编排。Agensh 去掉中心编排者，让 1024 个并发智能体自行认领子任务、共享发现、合并进度；DynaFlow 学习自由形式的编排；MetaAgent-X 端到端 RL 训练多智能体系统；多智能体 RL 何时改进工作流给出规模与策略共享的权衡；流式通信与跨模型 KV 缓存迁移降低协作延迟；组相对技能信用分配回答"团队里该改哪个智能体"；MiniCorp 训练由智能体组成的企业。

3.5 实践要点与开放问题

实践上：从成熟 harness 起步（Claude Code / Agent SDK、Codex、OpenHands），先改提示、工具与权限，再考虑改循环；AGENTS.md 简短、具体、可执行；反复出现的流程沉淀为技能，每个技能一句话说清"何时用"；多智能体只用于可并行、上下文可隔离的子任务；任何 harness 改动都用固定评测集回归并比较成本。

开放问题：harness 自我改进如何避免过拟合、奖励作弊与能力倒退？技能库膨胀后的检索、冲突与供应链安全？多智能体的信用分配与失败归因（LongRCA Bench）？

5 应用：编码与终端智能体

5.1 为什么编码最先成熟

代码有天然的验证信号（编译、测试、类型检查、lint），环境是纯文本，训练数据海量，且用户（开发者）本身能审阅产出。因此编码智能体最先从演示走向日常：从补全，到修 issue，再到在后台并行处理多个任务、连续多日自主开发。

三种开源形态奠定了基础：SWE-agent（专门设计的智能体接口）、OpenHands（通用开发平台）、Agentless（定位—修复—验证三步流水线，不用复杂循环也有竞争力）。产品侧有 Claude Code、Codex、Gemini CLI、Aider、Cline；mini-swe-agent 证明只用 bash、约百行代码也能取得不错的成绩。

5.2 训练：可验证环境是燃料

SWE-Gym、R2E-Gym、SWE-smith、SWE-Factory、SWE-Universe（百万级）、SWE-World（免 Docker）把真实仓库变成训练环境；SWE-RL 用软件演化数据做 RL，Skywork-SWE 观察到数据扩展律，长上下文多轮 SWE RL 解决长轨迹训练，daVinci-Dev 做智能体原生的中期训练，SWE-Master 给出可复现的后训练配方。终端方向有 TermiGen 与终端数据工程；能力外延到 GPU 内核（CUDA Agent）与竞赛编程（GrandCode）。

评测从 SWE-bench 与 SWE-bench Verified 扩展到多语言（Multi-SWE-bench）、多模态（SWE-bench Multimodal）、真实外包任务（SWE-Lancer）、持续更新防污染（SWE-rebench）和终端（Terminal-Bench、论文）。终端智能体足以胜任企业自动化指出：很多企业流程用终端智能体比用 GUI 更可靠。

5.3 最近半年

  • 终端训练数据的工业化。CLI-Universe、Terminal-Universe（把智能体轨迹转化为环境）、终端环境演化、长程终端任务递归合成、CalibForge（对抗式求解器校准难度）、FACET（合成时保持原意与可执行状态）、扩展长程终端数据；RL 侧有 T1 与学习从错误状态恢复的 ReTerm。
  • 从修 bug 到从零构建。DeNovoSWE、ProgramGym 训练"从零生成完整仓库/复现程序"；Super Library Agent 同时维护多个相关应用；Harness-of-Harness 做多日自主开发；SpecFirst 主张先引出行为规格再写程序。
  • 验证成为瓶颈。验证视野指出编码奖励没有银弹，验证并不总比生成容易；Dockerless 训练免环境的程序验证器；Lean4AgenticRL 使用可验证的多层过程奖励；组内智能体评分改进代码智能体的优势估计。
  • 仓库上下文与交接。FastContext、SWE-Pruner Pro、CodeNib；交接税发现接手别人的轨迹时表现明显下降。
  • 会改进自己的编码智能体。Mendel Gödel Machine、Ouroboros、Terminal-RSI、SoL-Pi、Harness-策略联合优化。
  • 评测更接近真实开发。SWE-bench 是学会了还是背下了检验污染；SWE-Touch（用户同时改代码）、WideSWE（跨仓库）、RealSWE（现实用户请求）、AgentSWE（是否做出用户想要的东西）、SWE-Explore（如何探索代码库）、TUA-Bench 与 Long-Horizon-Terminal-Bench；游戏开发方向有 SWE-Game、GameCraft-Bench；SWE-MISBEHAVIOR 给编码智能体的越界行为分类。

5.4 实践要点与开放问题

推荐的协作流程是"探索 → 计划 → 编码 → 提交"（Claude Code 最佳实践）：先让智能体读代码、写计划，人审过计划再动手；测试先行，"测试通过"是明确的完成标准，禁止修改测试来过关；小步提交，一切改动可回滚；并行任务用独立的 git worktree 或容器；认真审 diff，不跳过 CI 与代码评审；常用命令和禁区写进 AGENTS.md。

开放问题：验证不完备时的奖励作弊；长期维护大型代码库；代码评审负担从"写"转移到"审"之后，团队流程与责任如何调整。

6.4 实践要点与开放问题

有 API 或命令行就别用 GUI；浏览器任务优先用 DOM / 可访问性树；在隔离的虚拟机或独立浏览器配置中运行，不登录不必要的账户；支付、发送、删除、提交表单前必须请人确认；网页与文档内容一律当作不可信输入。

开放问题：长程 GUI 任务的稳定性（弹窗、加载延迟、界面改版）；应用是否会为智能体提供原生接口，使 GUI 操作成为过渡形态。

7 应用：深度研究与科研智能体

7.1 深度研究

深度研究智能体在搜索、阅读、推理之间循环几十到上百步，最后写成带引用的报告。OpenAI Deep Research（2025-02）之后它成为各家标配。开源侧的主线是用 RL 训练：Search-R1、R1-Searcher、DeepResearcher（真实网络环境）、ZeroSearch（不调用真实搜索引擎）、Search-o1；再到 WebSailor、WebSailor-V2、WebExplorer、Tongyi DeepResearch、MiroThinker、DR Tulu（演化的评分细则）、OpenSeeker、OpenResearcher、DR-Venus（端侧）。

两个关键：难题驱动的数据（简单问题一搜就有答案，训练需要多跳、模糊、需要交叉验证的问题，如 WebShaper；对应评测 BrowseComp）与长程上下文管理（ReSum、AgentFold、IterResearch）。"找一个答案"与"把一张表填满"是两类任务（WideSearch），后者适合多智能体并行（WideSeek-R1、Anthropic 研究系统）。长文写作方向有 STORM 与 WebWeaver。评测：GAIA、DeepResearch Bench、Mind2Web 2、BrowseComp-Plus、DeepResearchEval。综述：深度研究系统、深度研究的 RL 基础。

  • 检索回到"直接和语料打交道"。直接语料交互、GrepSeek、相关性的新角色、Follow the Entities、自演化搜索索引。
  • 少搜、搜对。SAAS、屏蔽陈旧观测、性能与成本、SearchJev。
  • 数据与环境。QUEST（完全合成的任务）、OpenSeeker-v2、FORT-Searcher、DeepSearch-World、ABSeeker、Harness-1、LongTraceRL。
  • 并行与多模态。SearchSwarm、SearchOS-V1、OpenSearch-VL、HyperEyes、Video-DeepResearch、OneSearch-VL。
  • 自动研究。ARIS、ScientistOne、AutoResearchClaw、Dr. Claw、Spark-to-Paper、OmniScientist、EurekAgent；面向机器学习自身：Athanor、AutoSFT、MLExpert、Frontis-MA1、AutoTrainess；AI 研究团队由不同专长的智能体组成，在有限实验预算下自主探索线性注意力架构；OProver 做智能体式形式化证明。
  • 认真对待失败。智能体在自动研究中如何失败（100 个案例）、智能体能做开放式 AI 研究吗、深度研究智能体在哪里出错、False Frontiers（出题者作弊）、先学会评估再改进；评测 AutoLab、NatureBench、ResearchClawBench、SAEScientist-Bench、Into the Unknown。

开放问题：主动性的边界；行业部署的责任归属、审计与合规；个人数据在长期记忆中的保护。

9 训练智能体：环境、强化学习与自我改进

9.1 能力从哪里来

智能体模型。在预训练与中期训练中加入智能体数据，再用轨迹做 SFT、在环境里做 RL。代表有 Kimi K2、GLM-4.5、GLM-5、Kimi K2.5、Tongyi DeepResearch、Nex-N1、智能体持续预训练；小而高效的有 Nemotron 3 Nano、Nemotron 3 Super、Youtu-LLM。

智能体 RL。与单轮 RLVR 不同：工具输出不是模型生成的（通常不计入损失），奖励在几十轮之后才出现，rollout 昂贵且长短不一。训练系统需要异步与长轨迹支持（超越十轮、verl、Agent Lightning、VerlTool、AWorld）；算法要处理熵与信用分配（ARPO、熵调制策略梯度、AEPO、IGPO、树搜索 RL）；推理会坍缩（RAGEN-2）。揭秘智能体推理中的 RL给出实用配方，智能体 RL 全景做了综述。

环境。可执行、可验证的环境是新的"数据"：AgentGym-RL、环境扩展、EnvScaler、Agent World Model（用 LLM 模拟环境）、Agent-World；早期经验让智能体在没有奖励时从自身动作的后果中学习。

不改权重的自我改进。积累记忆、技能与更好的 harness（第 2、3 章）；改权重的自我演化有 R-Zero、Agent0、Hyperagents（改进自身的改进机制）。自我改进可以分三层：上下文与记忆（最便宜、可回滚）→ 技能与 harness（可读、可审计）→ 权重（最持久、最难回滚）。综述见自演化智能体与现代智能体系统的自我改进。

9.2 最近半年

  • 在策略蒸馏（OPD）的变体潮与现实检验。OPD 让学生自己采样、教师逐 token 打分，比 SFT 更贴合学生分布，比 RL 信号更密。变体有 TurnOPD、SEED、PR-OPD、RetireOPD、PivotOPD、AgentOPSD、自蒸馏智能体 RL。但 OPD 真的在蒸馏吗发现教师监督噪声很大、学生却不敏感，用一个固定的负优势就能达到相近效果；自蒸馏的现实检验在统一条件下重测十种方法（132 次训练、约 1.2 万 GPU 小时）。
  • 长程 RL 的稳定与信用分配。进度信号（ProAS、DeltaTTG、Tev）、多尺度优化（多尺度策略优化）、动态评分细则（DRACO）、熵调节（AEM）、树感知后验蒸馏（树感知后验蒸馏）；多步工具 RL 为何坍缩分析失败原因；长程 RL 需要 Muon 在仓库级 issue 修复上给出单 rollout 异步配方。
  • 训练系统规模化。NeMo-DCR（万亿参数级、按位精确）、QwenGyre（弹性 RL）、Molt、单 rollout 异步优化、TRACE（rollout 预算分配）。
  • 训练"整个智能体"。Agent Lightning v1.0、LEGO-RL、ClawGym II、训练整个智能体而不只是模型、Harness Scaling、OPID、NeoHorse-1。
  • 环境合成成为独立方向。Qwen-AgentWorld、从受训者到训练者、CompoWorld、Skill2Env、从已解机制生成环境、AgentGarten、WorkRover、EAU、智能体语言世界模型、MIMESIS（用户模拟器）；数据质量：什么是好的智能体数据、Trajectory2Gym、不要掩盖环境、Agent Error Dataset；开放配方 OpenThoughts-Agent；综述 智能体环境工程。
  • 递归自我改进有了评测。RSI Arena、EvalResearchBench、S3Gym、Aspire；最后一个人类造的 AI、Atria Dawn、可信的递归自我改进讨论路线与安全边界。
  • 为智能体而生的模型与效率。Nemotron 3 Ultra、Agents-A1、Macaron-V1、MiMo-V2.6、IQuest-Q1、Sage-A1.5、Muse Glimmer 30B、Intern-S2-Preview；效率：推理力度的经济学、轨迹级推测执行、DLite、EdgeWise、TAO、Mix-Quant。

9.3 实践要点与开放问题

多数团队不需要训练：先把提示、工具、技能和 harness 做好。真要训练时，先收集真实轨迹与失败案例，构造可自动判分的环境，SFT 冷启动、RL 精调；人工抽查轨迹找奖励作弊；小模型 + 好 harness + 合适的推理力度常比大模型更划算。

11 安全与可靠性

11.1 三类风险

外部攻击。间接提示注入：网页、文档、邮件、工具输出里夹带指令（Greshake 等，2023-02）；工具与技能投毒、供应链攻击。模型自身的行为。越界、欺骗、奖励作弊、压力下的失准（Agentic Misalignment）。系统可靠性。不可逆操作、误删、长期部署中的退化。

11.2 防御原则

  • 致命三要素（Simon Willison）：同时具备私有数据访问、不可信内容输入、对外通信能力的智能体，可以被注入后外泄数据。三者至少去掉一个。
  • 从设计上隔离：CaMeL 让受信任的模型只根据用户指令生成程序，不可信数据只作为值流过程序、不能改变控制流；"先计划、后执行"、双模型模式同理。
  • 权限与沙箱：默认只读、写操作限定目录、网络出口白名单、凭证不进入模型上下文、不可逆操作逐次确认、全量审计日志。
  • 评测与红队：InjecAgent、AgentDojo、WASP、AgentHarm、ToolEmu、Agent Security Bench、Agent-SafetyBench、OpenAgentSafety、R-Judge、遵循策略智能体的红队、X-Teaming、T-MAP。护栏：AgentDoG、Spider-Sense、OS-Sentinel。开放环境的观察：Agents of Chaos、Moltbook 背后的恶魔、涌现的社会智能风险。

11.3 最近半年

  • 安全下沉到系统层。AgentKernel（信任原生的智能体操作系统）、Agentic Transaction（ACID）、UndoBench（把完成任务与能否撤销分开评测）、审计智能体 harness 安全、SkillHarness、EvoSafeHarness、SeerGuard。
  • 自演化带来的新攻击面。SkillJack（持久的技能后门）、SkillMarker（技能水印）、False Frontiers。
  • 度量模型自身的不当行为。DecepEval、SWE-MISBEHAVIOR、认知引发的风险；正向能力 Agentic Abstention、经验式置信估计、Thinking-in-Bets。
  • 多智能体与隐私。涌现共谋、Covert Assistance、Agent Mosaic、GateMem、MemPrivacy、MemSyco-Bench。
  • 红队与审计工具化。DTap、OpenART、AdvSim2Real、HazardAuditor、APEX-Harm、TraceDance、智能体到底做了什么、AgentDoG 1.5。

11.4 实践要点与开放问题

对照致命三要素检查每个智能体；沙箱运行、默认只读、网络与文件系统按需开放；删除、付款、发送、部署需要人确认并保留撤销手段；只安装可信来源的 MCP 服务器与技能；记录完整轨迹并抽样复查。

开放问题：提示注入没有通用的模型层解法，只能靠架构隔离降低影响；长期运行、自我演化的智能体如何持续保持对齐与可审计。

12 实践入门指南

本章把前面的经验压缩成十步。三条核心原则：先用最简单的方案；先建评测再迭代；权限从小开始。代码用 Anthropic Python SDK（pip install anthropic），换成其他厂商的 SDK，结构完全相同。

12.1 判断是否真的需要智能体

12.3 写一个最小的智能体循环

一个只读的"代码库问答"智能体：两个工具，只能看 workspace/ 目录，最多 20 步。

import pathlib
import anthropic

ROOT = pathlib.Path("workspace").resolve()   # 智能体只能看到这个目录
client = anthropic.Anthropic()               # 从环境变量 ANTHROPIC_API_KEY 读取密钥

TOOLS = [
    {"name": "list_dir",
     "description": "列出 workspace 中某个目录的内容。path 是相对路径，默认 '.'。",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}}}},
    {"name": "read_file",
     "description": "读取 workspace 中的文本文件，最多返回 20000 个字符。",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}},
                      "required": ["path"]}},
]

def safe_path(rel):
    p = (ROOT / rel).resolve()
    if not p.is_relative_to(ROOT):               # 防止 ../ 逃出工作目录
        raise ValueError(f"{rel} 不在 workspace 内")
    return p

def run_tool(name, args):
    if name == "list_dir":
        d = safe_path(args.get("path", "."))
        return "\n".join(sorted(x.name + ("/" if x.is_dir() else "") for x in d.iterdir()))
    if name == "read_file":
        return safe_path(args["path"]).read_text(errors="replace")[:20000]
    raise ValueError(f"未知工具 {name}")

def run_agent(task, max_steps=20):
    messages = [{"role": "user", "content": task}]
    for _ in range(max_steps):
        resp = client.messages.create(
            model="claude-opus-5-5", max_tokens=16000,
            system="你是代码库助手。先用工具查看文件再回答，并注明依据的文件。",
            tools=TOOLS, messages=messages)
        messages.append({"role": "assistant", "content": resp.content})
        if resp.stop_reason == "pause_turn":     # 服务端暂停了长回合：原样续上
            continue
        if resp.stop_reason != "tool_use":       # end_turn 正常结束；max_tokens、refusal 需另行处理
            text = "".join(b.text for b in resp.content if b.type == "text")
            return text, resp.stop_reason
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            try:
                out, err = run_tool(b.name, b.input), False
            except Exception as e:                # 错误交还给模型，让它自己纠正
                out, err = f"Error: {e}", True
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": out, "is_error": err})
        messages.append({"role": "user", "content": results})   # 所有结果放在同一条消息里
    return "达到步数上限", "max_steps"

answer, why = run_agent("这个项目是做什么的？入口在哪里？")
print(why, answer, sep="\n")

要点：助手消息原样追加（包括思考块与工具调用块）；一轮里的所有工具结果放进同一条用户消息；工具出错时返回 is_error 而不是中断；用步数上限兜底。不想手写循环时，SDK 的 Tool Runner 可以自动执行这个循环：用 @beta_tool 装饰普通函数（函数签名与文档字符串会变成工具 schema），再调用 client.beta.messages.tool_runner(model=..., max_tokens=..., tools=[...], messages=[...]) 并迭代结果。生产环境还要处理 refusal 与 max_tokens 停止原因、加重试与日志，长输出改用流式接口。

练习：加一个 write_file 工具，在执行前打印将要写入的内容并等待人工输入 y/n；再加一个 run_tests 工具，在容器里运行测试并返回最后 100 行输出。

12.4 把工具设计好

  • 少而精：按"用户要完成的事"设计工具（如 search_orders），而不是把每个底层 API 都暴露出去。
  • 描述写清楚何时用、何时不用、参数格式和返回内容；给出一两个例子。
  • 返回对模型有用的信息：人能读懂的字段而不是内部 ID；结果太长就分页或截断，并说明还有多少。
  • 错误信息要可操作：说清哪里错了、该怎么改。
  • 可复用的工具做成 MCP 服务器；写操作的工具单独标注并加确认。参考为智能体编写工具。

12.5 管理上下文与状态

系统提示与工具定义放在稳定的前缀以命中缓存；长任务让智能体维护 progress.md 与待办清单；工具输出只保留需要的部分；探索性工作交给子智能体，只取回结论；接近上限时压缩旧轮次。详见第 2 章与 Manus 的上下文工程。

12.6 把经验沉淀到 harness、AGENTS.md 与技能

智能体犯过一次的错，写进 AGENTS.md（项目约定）或做成技能（可复用流程 + 脚本），而不是每次在对话里纠正。技能只在上下文中放名称与一句描述，用到时再加载全文（Agent Skills）。长时任务参考长时运行 harness：先初始化环境与进度文件，再每次推进一小步并提交。

12.7 先建评测，再迭代

准备 20–50 个真实任务与可检查的完成标准；每个任务跑 3–5 次，记录成功率、成本、延迟；程序判分优先，LLM 评审需配评分细则并与人工对齐。每次改提示、工具、模型或 harness 都跑回归。追踪每一步（Langfuse、Phoenix、Inspect），每周读轨迹找新的失败模式。

12.8 加上安全护栏

  • 对照致命三要素：私有数据、不可信内容、对外通信，至少去掉一项。
  • 沙箱执行（容器、虚拟机或托管沙箱）；默认只读；网络出口白名单；凭证不进上下文。
  • 不可逆操作（删除、付款、发送、部署）前请人确认；保留撤销手段与审计日志。
  • 只用可信来源的 MCP 服务器与技能；把网页、邮件、文档内容一律当作数据，不当作指令。

12.9 控制成本与延迟

提示缓存是最大的一笔节省；按步骤难度选模型与推理力度；无依赖的工具调用并行；限制步数与单任务预算；批量离线任务用批处理接口。把"每个成功任务的成本"作为核心指标，而不是每次调用的成本。

12.10 上线与运维

灰度发布：先只读，再"起草 + 人审"，最后才自动执行；监控成功率、人工接管率、成本与异常动作；固定模型版本，升级前跑评测；收集用户修改与差评作为新的评测数据；长期运行的智能体定期复查记忆与技能，防止"衰老"（智能体也会衰老）。

12.11 四周学习路径与常见错误

  • 第 1 周 · 用：每天用一个编码智能体完成真实任务；读 Building effective agents 与 A practical guide to building agents。
  • 第 2 周 · 写：手写上面的循环，加写文件工具与确认机制；把一个工具做成 MCP 服务器；读 ReAct、SWE-agent、工具设计。
  • 第 3 周 · 评：为自己的场景做 20 个任务的评测集，比较两种模型或两种提示的成功率与成本；读 AI Agents That Matter、τ-bench。
